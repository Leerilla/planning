# 자료 작성 표준 (LECTURE_FORMAT.md)

본 표준은 강의 자료(`.md`)를 작성하기 위한 규칙이다. 이 규칙에 따라 작성된 자료는 별도의 변환 작업 없이 Next.js 슬라이드 사이트로 빌드된다.

작성 시점에 슬라이드 구조가 결정되도록 만드는 것이 본 표준의 목적이다.

---

## 1. 헤더 4계층

| 레벨 | 의미 | 사용 횟수 |
| --- | --- | --- |
| `#` | 수업 전체 제목 | 파일당 1개 |
| `##` | 이론/실습 구분 | 정확히 2개 ("이론", "실습") |
| `###` | 챕터 (서브 세션) | N개 |
| `####` | 슬라이드 묶음 (1-5장) | N개 |

### `#` — 수업 전체 제목

파일 맨 위에 하나만. 강의 사이트의 최상위 제목으로 사용된다.

```markdown
# 기획의 본질과 문제 발견
```

### `##` — 이론/실습 구분

정확히 두 개. "이론"과 "실습"으로 고정. 사이트에서 탭이나 섹션 분기점이 된다.

```markdown
## 이론
...

## 실습
...
```

### `###` — 챕터 (서브 세션)

이론·실습 각각 안에서 챕터를 나눈다. 번호 이모지(1️⃣, 2️⃣) 또는 일반 번호로 시작.

```markdown
### 1️⃣ 기획이란 무엇인가
### 2️⃣ AI 시대 기획의 변화
```

각 `###`는 사이트의 좌측 네비게이션에 챕터로 노출된다.

### `####` — 슬라이드 묶음

**가장 중요한 레벨이다.** `####` 하나가 1-5장의 슬라이드로 펼쳐진다.

```markdown
#### 기획의 정의
```

- 한 `####` 안의 콘텐츠가 한 슬라이드에 다 들어가면 1장
- 분량이 많거나 흐름을 끊고 싶으면 `---`로 자른다 (최대 5장까지)

---

## 2. `####` 안에서 슬라이드 자르기

`####` 안에서 슬라이드를 더 자르려면 `---`(수평선)을 사용한다.

```markdown
#### 기획의 정의

기획은 누구의 어떤 문제를 어떻게 풀 것인가의 답을 정의하는 일이다.

---

세 개의 핵심 질문:
- 누구 (페르소나)
- 어떤 문제 (페인포인트)
- 어떻게 (솔루션)
```

위 예시는 **2장의 슬라이드**로 변환된다.

### 자르는 시점의 판단 기준

다음 중 하나에 해당하면 `---`로 자른다.

- 핵심 메시지가 바뀜 (개념 정의 → 적용 사례)
- 시각적 표현 방식이 바뀜 (텍스트 → 표)
- 한 슬라이드에 담기엔 분량이 많음 (4문장 초과 또는 슬롯 4개 초과)
- 라이브 강의에서 호흡을 끊고 싶은 지점

### 1-5장 가변의 의미

- 1장: 짧은 개념, 한 단정, 용어 정의
- 2-3장: 일반적인 콘텐츠 (정의 → 예시, 개념 → 적용)
- 4-5장: 복합 콘텐츠 (단계별 설명, 여러 사례 묶음)

5장을 초과하면 `####`를 두 개로 쪼개는 것을 고려한다. 한 묶음이 너무 크다는 신호다.

---

## 3. 슬라이드 콘텐츠 작성 규칙

각 슬라이드(= `####` 하나 또는 `---`로 잘린 단위)는 다음 구조를 따른다.

```markdown
#### {제목}

{본문: 핵심 메시지 + 부연 설명}

::: aside
{자습 모드 전용 보충 설명}
:::
```

### 핵심 메시지

각 슬라이드의 첫 단락은 **핵심 메시지**이다. 한 문장이 이상적이며, 길어도 두 문장을 넘기지 않는다.

```markdown
#### 기획의 정의

기획은 누구의 어떤 문제를 어떻게 풀 것인가의 답을 정의하는 일이다.

세 질문 중 하나라도 모호하면 기획이 아니다.
```

### `::: aside` 블록

자습 모드에서만 펼쳐지는 보충 설명. 라이브 강의에서는 강사가 입으로 풀어줄 내용.

```markdown
::: aside
"AI로 멋진 것을 만들고 싶다"는 누구·문제·방법 어느 것도 답하지 않는다.
이것은 욕망이지 기획이 아니다.
:::
```

- 슬라이드당 1개까지
- 3-4문장 이내
- 핵심 메시지를 보충하되, 핵심 메시지 없이도 슬라이드가 성립해야 함

### 강조 인용 (`>` 블록)

핵심 단정을 강조할 때 사용. 이 패턴은 자동으로 `quote` 타입 슬라이드가 된다.

```markdown
#### 첫 단정

> 기능을 정하기 전에 사람과 문제를 정한다.

좋은 기획은 페르소나에서 출발하기 때문에 검증 가능하다.
```

### 표

비교나 정리는 표로. 이 패턴은 자동으로 `comparison` 또는 `terms` 타입이 된다.

```markdown
#### 좋은 기획 vs 나쁜 기획

| 구분 | 좋은 기획 | 나쁜 기획 |
| --- | --- | --- |
| 출발점 | 페르소나 | 기능 |
| 검증 | 가능 | 불가능 |
```

### 번호 리스트

단계나 절차는 번호 리스트로. 이 패턴은 자동으로 `process` 타입이 된다.

```markdown
#### 기획 5단계 프레임

1. 문제 — 한 문장의 페인포인트
2. 페르소나 — 가설 페르소나 6줄
3. 가설 — 검증 가능한 가설 3개
4. 검증 — 능동·수동 데이터
5. 정제 — PRD + 기능명세
```

## 4. 자료 전체 구조 예시

```markdown
# 기획의 본질과 문제 발견

## 이론

### 1️⃣ 기획이란 무엇인가

#### 기획의 정의
{슬라이드 1}

---

{슬라이드 2}

#### 좋은 기획 vs 나쁜 기획
{슬라이드 1: 비교 표}

#### 첫 단정
> {단정}

{맥락 설명}

#### 5 Whys
{슬라이드 1: 개념}

---

{슬라이드 2: 적용 사례}

### 2️⃣ AI 시대 기획의 변화

#### 빨라진 것
...

## 실습

### 활동 묶음 1: 아이디어 선택과 1차 리서치

#### 1-1. 아이디어 선택
...
```

---

## 5. 작성 시 자가 점검 체크리스트

자료 작성 후 다음을 점검한다.

- [ ] `#`이 정확히 1개인가
- [ ] `##`이 "이론"과 "실습" 두 개인가
- [ ] 모든 `###` 챕터에 `####` 슬라이드 묶음이 1개 이상 있는가
- [ ] 어떤 `####`도 5장을 초과하지 않는가
- [ ] 각 슬라이드(= `####` 또는 `---` 단위)의 핵심 메시지가 한두 문장인가
- [ ] `::: aside`가 슬라이드당 1개를 넘지 않는가
- [ ] 표·번호 리스트·`>` 인용 중 한 가지가 명확하게 쓰였는가 (혼합 시 자동 매핑 어긋날 수 있음)

---

## 6. 빌드 흐름

```
[작성] lecture.md
   ↓
[파싱] # → 사이트 제목
       ## → 이론/실습 분기
       ### → 챕터 (네비게이션)
       #### + --- → 슬라이드 단위
   ↓
[자동 매핑] 콘텐츠 패턴 → 슬라이드 타입 (SLIDE_GUIDE.md 참조)
   ↓
[렌더링] 각 슬라이드 → React 컴포넌트
   ↓
[빌드] Next.js 정적 사이트
```
