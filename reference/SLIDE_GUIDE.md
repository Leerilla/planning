# 슬라이드 변환 규칙 (SLIDE_GUIDE.md)

본 가이드는 `LECTURE_FORMAT.md` 규칙으로 작성된 자료를 슬라이드 컴포넌트로 변환하는 규칙이다. **Claude Code가 이 파일을 컨텍스트로 읽고 변환·검증 작업을 수행한다.**

핵심 원칙: **슬라이드 타입은 콘텐츠 패턴으로 자동 결정**된다. 작성자가 frontmatter로 타입을 지정하지 않는다.

---

## 1. 슬라이드 단위 식별

자료에서 슬라이드 단위는 다음 두 가지로 식별된다.

1. `####` 헤더 (새 슬라이드 묶음 시작)
2. `####` 안의 `---` 수평선 (같은 묶음 내 다음 슬라이드)

```markdown
#### 기획의 정의       ← 슬라이드 1 시작

본문...

---                     ← 슬라이드 2 시작

본문...

#### 좋은 기획 vs 나쁜 기획   ← 슬라이드 3 시작 (새 묶음)
```

`###`, `##`, `#`은 슬라이드 경계가 아니다. 챕터 표지(title 슬라이드)는 `###` 헤더 정보를 자동으로 사용한다.

---

## 2. 슬라이드 타입 자동 매핑

각 슬라이드의 콘텐츠 패턴을 분석해 타입을 결정한다. **우선순위 순으로 매칭**한다.

매핑 원칙: **명시적 의도(키워드·구조)가 콘텐츠 패턴을 이긴다.** 작성자가 "사례:"를 쓴 건 명백한 의도 표명이므로, 번호 리스트가 있어도 `example`로 잡힌다.

| 우선순위 | 조건 | 타입 | 비고 |
| --- | --- | --- | --- |
| 1 | `실습` 섹션(`##`) 하위의 모든 슬라이드 | `activity` | 섹션 컨텍스트 최우선 |
| 2 | 슬라이드가 `###` 직후 첫 콘텐츠 없이 시작 | `title` | 챕터 표지로 자동 생성 |
| 3 | 첫 단락이 "사례:" "예시:" "시나리오:"로 시작 | `example` | 명시적 키워드 |
| 4 | `>` 블록이 슬라이드 첫 콘텐츠로 등장 | `quote` | 강조 단정 슬라이드 |
| 5 | 표 + 헤더 2열(용어 \| 설명 형태) | `terms` | 용어 해설 |
| 6 | 표 + 헤더 3열 이상 (비교) | `comparison` | 좋은/나쁜, A/B 비교 |
| 7 | 번호 리스트(1. 2. 3.)가 3개 이상 항목으로 존재 | `process` | 단계/플로우 |
| 8 | 위 어디에도 해당하지 않음 | `concept` | 기본 타입 (개념 설명) |

### 우선순위 적용 예시

다음 슬라이드는 번호 리스트 5개와 "사례:" 키워드를 모두 가지지만, **우선순위 3(`example`)이 7(`process`)을 이긴다.**

```markdown
#### 5 Whys 적용

사례: 회의록 정리 문제에 5 Whys를 적용해보자.

증상: 회의록 정리에 시간이 많이 든다

1. 왜? 발언을 다 받아쓰지 못해 영상을 다시 본다
2. 왜? 회의 중 다음 안건 진행으로 받아쓸 여유가 없다
3. 왜? 액션아이템을 그 자리에서 분류해야 한다
4. 왜? 누락이 다음 주 진행을 막는다
5. 왜? 재합의에 별도 회의가 필요하다

결론: 진짜 문제는 "정리 시간"이 아니라 "재합의 비용"이다.
```

→ 타입: `example` (사례 키워드가 번호 리스트보다 우선)

### 매핑 어긋날 때의 보정

자동 매핑이 작성자 의도와 다르면, **콘텐츠를 고친다 (frontmatter 추가가 아니라).**

| 문제 상황 | 해결 방법 |
| --- | --- |
| 개념 설명인데 `comparison`으로 잡힘 | 표를 제거하거나 본문 텍스트를 늘림 |
| 사례인데 `concept`으로 잡힘 | 첫 단락에 "사례:" 또는 "예시:" 명시 |
| 단계 설명인데 `concept`으로 잡힘 | 번호 리스트(1. 2. 3.)를 3개 이상으로 |
| 단정인데 `concept`으로 잡힘 | `>` 인용 블록을 본문 앞에 배치 |

### 예외: frontmatter 오버라이드

자동 매핑이 어떻게 해도 어긋나는 특수 케이스만 frontmatter로 명시. **전체 슬라이드의 5% 미만이어야 한다.**

```markdown
#### 특수 슬라이드

<!-- slide-type: quote -->

여기서는 강제로 quote 타입으로 변환된다.
```

## 3. 각 타입의 컴포넌트 매핑

| 타입 | 컴포넌트 | 슬롯 |
| --- | --- | --- |
| `title` | `<TitleSlide>` | 챕터 번호, 제목, 부제, 학습 목표 |
| `concept` | `<ConceptSlide>` | 제목, 핵심 메시지, 부연 설명, aside |
| `comparison` | `<ComparisonSlide>` | 제목, 비교 표, 요약 |
| `process` | `<ProcessSlide>` | 제목, 단계 리스트, 설명, aside |
| `example` | `<ExampleSlide>` | 제목, 시나리오, 단계별 적용, 결론 |
| `quote` | `<QuoteSlide>` | 인용문, 맥락 설명 |
| `activity` | `<ActivitySlide>` | 제목, 목표, 절차, 체크리스트 |
| `terms` | `<TermsSlide>` | 제목, 용어 표 |

---

## 4. `::: aside` 블록 처리

자습 모드 전용 보충 설명. 라이브 모드에서는 숨김.

```markdown
::: aside
보충 설명
:::
```

- 슬라이드당 1개까지
- 컴포넌트에서 토글로 펼쳐지는 영역
- 자동 매핑에는 영향을 주지 않음 (본문 분석에서 제외)

## 5. 챕터 표지 자동 생성

`###` 헤더 직후 `####` 헤더가 바로 나오면, 챕터 표지 슬라이드가 자동 생성된다.

```markdown
### 1️⃣ 기획이란 무엇인가

#### 기획의 정의   ← 첫 콘텐츠 슬라이드
```

위 경우 변환 결과:

```
[자동 생성] 챕터 표지 슬라이드 (title 타입)
  - 챕터 번호: "1️⃣"
  - 제목: "기획이란 무엇인가"
[변환] 기획의 정의 (concept 타입)
```

### 챕터 표지에 학습 목표를 명시하고 싶을 때

`###` 헤더 직후 `####` 없이 본문을 두면, 그 본문이 챕터 표지의 학습 목표가 된다.

```markdown
### 1️⃣ 기획이란 무엇인가

이 챕터를 학습한 뒤 다음을 할 수 있다.
- 좋은 기획과 나쁜 기획을 한 문장으로 구분한다
- 문제를 5 Whys로 한 단계 더 깊게 파고든다

#### 기획의 정의
```

## 6. 검증 단계 (빌드 시점)

파싱 시 다음을 검증하고, 위반 시 빌드 에러를 발생시킨다.

| 검증 항목 | 위반 시 |
| --- | --- |
| `#`이 정확히 1개 | ❌ 빌드 에러 |
| `##`이 "이론"과 "실습" 두 개 | ❌ 빌드 에러 |
| 모든 `###` 하위에 `####` 또는 본문 존재 | ❌ 빌드 에러 |
| 한 `####`의 슬라이드 수가 5장 이하 | ⚠️ 경고 |
| 각 슬라이드의 타입이 결정됨 | ❌ 빌드 에러 |
| `::: aside` 블록이 슬라이드당 1개 이하 | ⚠️ 경고 |

## 7. Claude Code 작업 명령 예시

### 변환

```
@lecture.md 파일을 @LECTURE_FORMAT.md와 @SLIDE_GUIDE.md 규칙에 따라
슬라이드 데이터로 변환해줘.
각 슬라이드의 타입을 자동 매핑 표 기준으로 결정하고,
어떤 슬라이드가 어떤 타입으로 매핑됐는지 표로 보고해줘.
```

### 검증

```
@lecture.md 파일이 @LECTURE_FORMAT.md 규칙을 따르는지 검증해줘.
위반 사항이 있으면 위치(라인 번호)와 함께 보고해줘.
```

### 매핑 시뮬레이션

```
@lecture.md를 파싱했을 때 슬라이드가 총 몇 장 나오는지,
각 타입별로 몇 장씩 나오는지 시뮬레이션해줘.
```
