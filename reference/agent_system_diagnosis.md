**작성일**: 2026-05-10
**대상**: Claude Code 풀사이클 21시간 학습 PPT 플랫폼의 8-agent 큐레이션 시스템
**진단 자료**: CLAUDE.md, S1/S2 lecture.md, 8개 sub-agent 명세, history.md, assignment.md, checklist.md
**진단자 관점**: Agent 설계 원리 + Sub-agent 협업 시스템 분석

## 0. 한 줄 진단

> **이 시스템은 "위반 검출(감산)" 메커니즘을 7중으로 쌓아놓고, "메시지 만들기(가산)" 메커니즘은 1개뿐이다. 사용자가 호소하는 8개 문제는 모두 이 비대칭에서 파생된 같은 증상이다.**

## 1. 근본 원인 (Root Cause): 가산-감산 비대칭

### 1-1. 시스템 전체 검증 축의 통계

자료 분석 결과, 8개 agent의 검증 축을 모두 합산하면:

| Agent | 검증 축 수 | 성격 |
|---|---|---|
| layout-validator | 5축 (정량) | 줄바꿈/카드편차/모바일/영역/일관성 |
| plan-reviewer | 8축 + **36개 결정 위반 0건** | 규정 |
| content-quality-reviewer | 5+2축 (흐름 강도 점수) | 학습자 흐름 |
| design-reviewer | 8개 grep + 6개 검증항목 | 디자인 토큰 |
| capture-validator | 5축 | 파일 무결성 |
| interactive-planner | E7~E9 자가검토 + 카탈로그 다양성 ≥3 | 사전 검증 |
| visual-planner | D12 시뮬 표 + F6 wireframe | 사전 검증 |
| slide-curator | Phase 7.5 자가 grep 5축 | 사전 검증 |

**합계**: ~30개 검증 축 + 36개 누적 결정 위반 차단 = **약 66개의 "절대 통과해야 하는 게이트"**

### 1-2. 가산형 평가 축의 부재

위 66개는 모두 **"위반 검출(감산형)"**입니다. 즉 *나쁜 것을 발견하면 fail* 구조입니다.

전체 시스템에 다음 평가 축은 **0개**입니다:

- ❌ "이 슬라이드는 새로운 패턴인가" (창의성)
- ❌ "이 세션 성격에 맞는 슬라이드 수인가" (적합성)
- ❌ "lecture.md의 메시지 강도와 슬라이드 강도가 일치하는가" (충실성)
- ❌ "정적 PPT보다 인터랙티브가 더 강한가" (E7의 가산 측정)
- ❌ "이전 세션과 다른가" (다양성)

interactive-planner의 E9 "카탈로그 ≥ 3가지"는 *최소치 통과* 검증이지 *카탈로그 다양성을 가산 측정*하지 않습니다. visual-planner의 "신규 컴포넌트 자유 제안"은 권한만 있고 *제안하지 않은 경우의 패널티가 없습니다*.

### 1-3. 결과: "안전한 평균 해(safe average solution)" 수렴

이 비대칭의 수학적 결과는 명확합니다.

> **모든 검증을 통과하는 가장 안전한 출력 = 이전에 통과한 적 있는 패턴을 그대로 복제**

왜냐하면:
- **새 패턴 시도 = 미지의 위반 위험** (66개 중 1개라도 걸리면 회귀)
- **익숙한 패턴 복제 = 통과 보장** (이전에 통과한 이력이 있음)

이게 사용자께서 호소하는 핵심 문제 2 "**고정된 패턴, 장수**"의 직접 원인입니다. Agent들은 합리적으로 행동하고 있습니다 — 시스템이 그렇게 설계되어 있어서 그럴 수밖에 없는 겁니다.

## 2. history.md의 역설: "차단 시스템"의 자기강화

### 2-1. 현재 history.md 작동 방식

CLAUDE.md § "강사 결함 raw 기록" 섹션과 history.md § "🔁 반복 패턴 분석"을 종합하면:

```
강사 결함 1건 발생
  → history.md에 카테고리 분류로 기록
  → 카테고리가 3회 누적되면 "⭐ 트리거"
  → 다음 sprint에서 시스템 강화 적용
  → 신규 spec 검증 항목으로 자동 추가
  → 이후 모든 세션이 이 차단 룰 적용받음
```

history.md를 보면 이미 이렇게 누적된 차단 룰이 작동 중입니다:
- 특수문자/emoji 17건 → design-reviewer pre-build grep 강제
- 패턴 prop mismatch 6건 → wrapper props 자동 비교
- 라인 분할 7건 → 배열 처리 의무
- 텍스트 폭증 3건 → wrapper 단계 검증
- 톤 강제 3건 → content-quality-reviewer 톤 검증
- 가독성 8건 → 폭/폰트 시뮬 강화

### 2-2. 시스템적 결함

이 메커니즘에 **3가지 누적 결함**이 있습니다.

#### 결함 A: 차단 룰의 일방향성 — 누적만 되고 갱신/완화 안 됨

CLAUDE.md "Sprint 종료 시" 섹션과 history.md "⭐ 트리거" 룰은 **추가**만 명시합니다. **다음 항목이 어디에도 없습니다**:

- 차단 룰을 완화하는 메커니즘
- 차단 룰의 유효 기간 (예: 5세션 후 자동 만료)
- 세션 특성에 따른 차등 적용

→ 결과: S1에서 추가된 룰이 S9까지 그대로 적용. 세션 9개 거치면 차단 룰이 수십 개 누적됨.

#### 결함 B: 카테고리 일반화의 부작용

"톤 강제" 결함 3건이 누적되면 **"모든 톤을 부드럽게"**라는 룰이 시스템 전체에 적용됩니다. 그런데:

- S1 (기획 본질) — "기능부터 정하면 욕망에서 시작한다" 같은 부드러운 톤이 맞음 ✓
- 가설 검증 강조하는 슬라이드 — 강한 단정이 필요. "검증은 의견 수집이 아니다" (S2 lecture line 25)는 강하게 들려야 함 ✗

→ 룰이 일반화되면서 *원래 강해야 할 부분도 부드러워짐*. 이게 사용자 문제 4 "정답 단정"의 반대 증상으로 나타남.

#### 결함 C: 결함 = 정설(canon) 변환

history.md의 모든 결함은 강사 1인의 시각 검증 결과입니다. 이게 카테고리화되면 **모든 미래 세션에 적용되는 정설**이 됩니다. 이는 두 가지를 가정합니다:

1. 강사의 모든 결함 판정이 일관됨 (실제로는 그날의 컨디션·맥락 영향)
2. S1에서 발생한 결함 패턴이 S9까지 동일하게 유효함

→ **22건/30건/22건씩 누적되며 시스템이 점점 경직**되고 있습니다. 이 추세대로면 S9 즈음에는 새로운 슬라이드 형태가 나오는 게 거의 불가능해집니다.

### 2-3. 정량적 증거

history.md에 적힌 추세 자체가 결함을 보여줍니다:

> "S1 → S2: 30건 (대규모 회귀 → 단일 회귀로 비용 81% 감소)"
> "S2 → S3: 22건 (Phase O.1 강화로 빌드 전 사전 차단 일부 효과)"
> "S4 큐레이션 시 목표: ≤ 5건"

표면적으로는 결함이 줄어들고 있어 보입니다. 그러나 **결함이 줄어드는 이유**가 두 가지로 갈립니다:

1. **(긍정) 시스템이 진짜 좋아짐** — 가능성
2. **(부정) 슬라이드가 점점 비슷해짐** — 가능성

사용자께서 호소하시는 핵심 문제 2 "고정된 패턴, 장수"는 **2번이 진실**임을 시사합니다.

## 3. session 특성 분기의 부재

### 3-1. S1과 S2 lecture.md 비교 (실제 자료 기반)

| 항목 | S1 (기획 본질) | S2 (고객 검증) |
|---|---|---|
| **본질** | 개념 정립 (기획이란 무엇인가) | 방법론 (검증을 어떻게) |
| **단정 수** | 3개 (C5/C6/C7로 고정) | 3개 (별도) |
| **이론:활동 비율** | 약 6:4 (이론 무거움) | 약 5:5 (균형) |
| **핵심 원리** | 5단계 사슬 (선형) | 두 축 병렬 (능동/수동) |
| **인터랙티브 적합 요소** | 사슬 시각화, 좋은/나쁜 비교, 페르소나 5축 빌더 | **두 축 동시 시뮬, 메타프롬프팅 단계, 응답률 게이지, 채널별 비교** |
| **시각 자료의 핵심** | 정적 다이어그램 우세 | **동적 비교/병렬 우세** |
| **활동 산출물** | 워크시트(텍스트) | 카피(텍스트) + 스크래핑 데이터(표) |

이 둘은 **시각 자료의 본질이 다릅니다**. S1은 *순서·계층*이 핵심이고, S2는 *대비·병렬*이 핵심입니다.

### 3-2. 워크플로우의 처리

그런데 slide-curator의 Phase 4 "분류 검증"은:

> "이론/활동 구간 자동 식별"
> "이론 시퀀스 길이 가이드: 20장 / 25장 / 30장"

이게 전부입니다. 즉:

- 이론/활동의 **이진 분류**만 함
- 길이는 **세 단계 사이즈** 중 선택
- 세션의 *논리 구조*(선형/병렬/순환)는 입력 변수가 **아님**

interactive-planner도:

> "이론 덱 30장당 최소 4~5건 인터랙티브"

→ **모든 세션 동일한 밀도**. S1처럼 단계별 사슬이 핵심이면 4-5건이 맞을 수 있지만, S2처럼 *두 축 동시 시뮬*이 핵심이면 이게 부족합니다 (메타프롬프팅 비교, 응답률 비교, 채널 비교, 능동/수동 비교 = 최소 4-6건이 *비교 시각화* 하나에서만 필요).

### 3-3. 결과

- **문제 5 "session별로 다른 형식이 필요한데 균일"** = 직접 원인
- **문제 1 "인터랙티브 3-5개 고정"** = 모든 세션이 같은 권장 밀도를 받기 때문

세션 특성에 따라 *동적으로 분기*하는 단계가 워크플로우 어디에도 없습니다.

## 4. 검증 게이트가 lecture.md를 무력화하는 메커니즘

### 4-1. 의도 vs 실제

CLAUDE.md 절대 원칙 2:
> "lecture.md ≠ 학생 본문. 학생은 큐레이션된 슬라이드만 봄"

CLAUDE.md A1:
> "lecture.md ≠ 학생 본문. 단순 변환 X — 재구성 필수"

A3:
> "lecture.md 본문 충실 인용 — desc / note / footer 한 줄 0건"

**의도**는: lecture.md를 *재구성*하되 *충실*하게 인용하라.

**실제 메커니즘**은: 다음 6단계를 거치는 동안 lecture.md의 원래 강도가 약화됩니다.

```
lecture.md (원본)
  ↓ slide-curator: 헤딩 트리 추출 + 4가지 콘텐츠 분류
  ↓ slide-curator: 18개 패턴 카탈로그에 강제 매핑
  ↓ interactive-planner: 6개 카탈로그 다양성 ≥ 3 강제
  ↓ visual-planner: 글자 수 임계값 강제 (KeyMessage 24자, Definition 80자)
  ↓ layout-validator: 5축 정량 검증 통과
  ↓ plan-reviewer: 36개 결정 위반 0건 통과
  ↓ content-quality-reviewer: 5+2축 통과
slide (산출)
```

각 단계마다 **위반 회피**가 우선이라, 원본의 강한 표현이 부드러워지고, 긴 부연이 단축되고, 새로운 메타포가 익숙한 패턴으로 매핑됩니다.

### 4-2. 정량적 증거 — S1 lecture line 32 "첫 단정"

S1 lecture에는 다음 강한 문장이 있습니다 (line 32):

> "**첫 단정: 기능을 정하기 전에 사람과 문제를 정한다.**"

이게 시스템에 들어가면:

1. **slide-curator**: KeyMessage 패턴에 매핑 (필수)
2. **visual-planner D12**: KeyMessage `message` 데스크톱 24자/줄, 모바일 12자/줄 임계값 적용 → **"기능을 정하기 전에 사람과 문제를 정한다"는 22자**, OK
3. 그러나 CLAUDE.md C5: 이 단정의 **공식 표현은 "기능은 답이고, 사람과 문제는 질문이다 / 질문부터 시작한다"** — lecture.md 원문과 다른 *시스템 정설*이 있음
4. **plan-reviewer**: C5 검증 → "공식 표현과 다름" 발견 → 회귀 강제

**결과**: lecture.md 원문이 시스템 정설로 *대체*됩니다. 이게 사용자 문제 4 "정답 단정"의 정체입니다 — 실제로는 lecture.md 자체가 정답이 아니라 **시스템에 누적된 정답이 강제**되고 있는 겁니다.

### 4-3. 어디에 누적되는가

CLAUDE.md § 🧠 강사 누적 결정:
- C1~C9 (9개 콘텐츠 결정)
- 그 중 C5/C6/C7는 **세 단정의 정확한 문구를 고정**

이게 위험한 이유:

- S1 lecture.md의 "첫 단정"은 lecture line 32에 살짝 다른 표현으로 등장 (현재형 vs 명사구)
- 시스템은 C5의 정확한 문구를 *정답*으로 강제
- 그래서 강사가 lecture.md를 자유롭게 쓰려고 해도 시스템이 "C5 위반"으로 회귀시킴

**결과**: 강사의 자유 메모(lecture.md)와 시스템의 정설이 충돌. 강사는 자기 표현을 수정해야 시스템을 통과할 수 있음. 이는 CLAUDE.md 절대 원칙 2 "lecture.md 형식은 강사 자유"를 자기 모순적으로 위반합니다.

## 5. 콘텐츠 누락의 메커니즘 (문제 3 진단)

### 5-1. 누락이 발생하는 5개 지점

자료 분석 결과 콘텐츠 누락이 발생할 수 있는 지점은 다음과 같습니다:

#### 지점 1: 헤딩 트리 추출 시
slide-curator Phase 3.2는 "헤딩 트리 추출"을 합니다. 그런데 S1 lecture.md를 보면:
- 핵심 콘텐츠가 **헤딩 사이의 평문**에 들어 있음 (예: line 32 "첫 단정"은 H3 "기획의 정의" 안의 인용 블록)
- "용어 해설" 표 (line 43-49)는 본문이지만 헤딩이 없음

→ 헤딩 트리 추출 중심이면 표·인용 블록·평문 내 강한 단정이 **누락 위험**.

#### 지점 2: 18개 패턴 카탈로그 매핑 시
slide-curator Phase 5.1: "단언문 → KeyMessage / 비교 → Comparison / 3가지 → ThreeCards / 함정 → Warning". 

그런데 S2 lecture line 53-56 같은 *예시 비교 문단*은 어느 패턴에도 명확히 매핑되지 않음:

> "시드 1번 기준으로 PM 친구에게 '이거 회의록 정리 자동화 도구 어때?'라고 물으면 친구는 '오, 좋다'라고 답할 가능성이 높다. 그러나 같은 친구에게 '최근 한 달 동안 회의 후 액션아이템 정리에 시간을 얼마나 썼는가...'를 물으면..."

이건 *서사형 대비*인데 18개 패턴에 *서사형 대비* 패턴이 없음. → 강제로 ThreeCards나 Comparison으로 매핑되면서 *서사의 흐름이 끊김* (또는 누락).

#### 지점 3: 섹션 분할 빌드 (F6)
Phase 7.0의 "§1 → 강사 검증 → §2 → 강사 검증 → §3" 흐름에서:
- §1과 §2 사이에 있어야 할 *전환 콘텐츠*가 어느 섹션에도 안 들어감
- S1 lecture line 76 "이 5단계 프레임 위에서 AI가 어떤 영향을 주는지가 다음 절의 주제이다" 같은 *brigde 문장*이 §1 끝인지 §2 시작인지 모호 → 누락 위험

#### 지점 4: 글자 수 임계값 강제 시
visual-planner D12 임계값 — Definition definition은 50자/줄, notes는 80자. 그런데 S1 lecture line 169 같은 문장:

> "원문이 진짜라도 신뢰 가능한지 작업자가 판단한다. 1차 자료인가, 2차 자료인가, 다른 출처와 교차 검증 가능한가, 본인 페르소나에 적용 가능한 정보인가."

이건 1문장 + 4개 질문 = 약 110자. 임계값 초과로 **분할 강제**됩니다. 분할하면서 *질문 간의 누적성*이 사라지고, 질문 4개 중 한두 개가 다음 슬라이드로 넘어가는 과정에서 **누락 위험** 발생.

#### 지점 5: history.md 차단 룰 적용 시
history.md의 누적 룰 중 "콘텐츠 두께 부족 → 한 줄 desc 0건 강제"는 *짧은 desc 차단*이지만, 동시에 "텍스트 폭증 → 임계값 초과 차단"이 *긴 desc 차단*이라 **두 룰의 충돌 영역**에서 콘텐츠가 사라짐.

### 5-2. 결과
사용자 문제 3 "콘텐츠 누락"은 **단일 원인이 아니라 5개 지점에서 동시에 발생하는 누적 손실**입니다. 한두 개 고친다고 해결되지 않습니다.
## 6. 8개 문제 vs 근본 원인 매핑

이제 사용자께서 호소하신 8개 문제와 2개 핵심 문제를 근본 원인에 매핑합니다.

| 사용자 문제 | 표면 증상 | 근본 원인 | 어디서 작동 |
|---|---|---|---|
| 1. 인터랙티브 3-5개 고정 | 카탈로그 부족 같음 | 가산-감산 비대칭 | interactive-planner E9 (최소치만 검증) + 모든 검증축이 감산형 |
| 2. 줄바꿈 이상 | 자동 줄바꿈 버그 같음 | 글자 수 임계값이 시각 폭과 무관 | visual-planner D12 (글자 수 기반, 시각 폭 무시) |
| 3. 콘텐츠 누락 | slide-curator 결함 같음 | 5개 지점 누적 손실 | 헤딩 트리 + 패턴 매핑 + 섹션 분할 + 임계값 + 차단 룰 충돌 |
| 4. 정답 단정 | 톤 문제 같음 | C5/C6/C7 시스템 정설 강제 | CLAUDE.md § 🧠 9개 콘텐츠 결정 |
| 5. session 균일 형식 | 분기 부족 같음 | session 특성이 입력 변수 아님 | slide-curator Phase 4 (이론/활동 이진 분류만) |
| 6. 슬라이드 장수 vs 두께 불균형 | 단순 텍스트 부족 | A3 한 줄 0건 + D12 상한이 충돌 | visual-planner D12 + history.md 차단 룰 |

| **핵심 2. 고정 패턴/장수** | 카탈로그 한정 | **가산-감산 비대칭 + history.md 누적 + session 분기 부재** | 시스템 전체 |

### 6-1. 문제 7 "특수문자 남용"의 자기참조성

이건 별도로 짚어야 합니다. 사용자께서 "§, — 등 특수문자 사용 빈도가 높다"고 하셨는데, **그 원인이 워크플로우 문서 자체**입니다.

자료 검색 결과:
- CLAUDE.md에서 "§" 사용: **20+ 회** (예: "§ 🧠 강사 누적 결정", "§ 1", "§ 📈")
- agent .md 파일에서 "§" 사용: **다수** (예: "§ 1", "§ 4.3", "§ 🔁")
- "↳", "⛳", "→", "—" 등 다수

design-reviewer는 "특수문자 차단 grep"을 학생 화면 영역에서 합니다. 그런데 모델이 학습/모방하는 것은 **워크플로우 문서 자체의 스타일**입니다. CLAUDE.md를 매번 읽고, agent .md를 매번 읽으니, 출력에 § ↳ ⛳ —이 자연히 들어옵니다.

**즉**: 차단 룰을 강화해도 시스템 프롬프트 자체가 같은 문자를 쓰고 있는 한, 그 문자는 다음 출력에 또 등장합니다.

## 7. 처방 (구조적 수정 방향)

표면 패치가 아니라 *구조 수정*을 제안합니다. 우선순위는 영향도 기준입니다.

### 처방 1 (P0, 가장 큰 영향): "session 특성 입력 변수" 도입 ⭐

**문제 해결**: 핵심 문제 2, 문제 1, 문제 5, 문제 6

#### 신설할 단계: Phase 0 — Session Profile 정의

slide-curator Phase 1 이전에 *session profile* 입력 단계 추가:

```
session_profile = {
  "logic_structure": "linear" | "parallel" | "cyclic" | "hierarchical",
  "core_visual_kind": "diagram" | "comparison" | "simulation" | "data",
  "interactivity_density": "low" | "medium" | "high",
  "tone_strength": "soft" | "balanced" | "strong",
  "expected_slide_count": int,
  "primary_chains": [...]  # 단정-근거 페어 수
}
```

이걸 강사가 lecture.md 작성 시 **YAML frontmatter**로 명시하거나, slide-curator가 Phase 3 분석 결과로 *제안* + 강사 승인.

#### 모든 후속 agent가 이 profile 참조:

- interactive-planner: 밀도를 profile.interactivity_density에 따라 동적 조정 (low: 3-5건, medium: 6-9건, high: 10-14건)
- visual-planner: 시각 카탈로그 우선순위를 profile.core_visual_kind에 따라 가중
- content-quality-reviewer: 톤 검증을 profile.tone_strength에 따라 차등
- plan-reviewer: 슬라이드 수 권장 범위를 profile.expected_slide_count ± 20%

#### 효과 추정:

- S1 (linear, diagram, medium, soft): 인터랙티브 5-6건, 부드러운 톤, 다이어그램 중심 — 현재와 비슷
- S2 (parallel, comparison, high, balanced): **인터랙티브 8-12건, 균형 톤, 좌우 비교 중심** — 현재 대비 다양성 폭증
- S3 (linear, simulation, medium, balanced): PRD/MVP 시뮬 중심
- 결과: 세션마다 형태가 다름 → 핵심 문제 2 해결의 50%

### 처방 2 (P0): 가산형 평가 축 신설

**문제 해결**: 핵심 문제 2, 문제 1, 문제 6

현재 0개인 가산형 축을 3개 신설:

#### 신설 축 A: 다양성 점수 (Diversity Score)

content-quality-reviewer 또는 plan-reviewer에 추가:

```
다양성 점수 = (사용된 패턴 종류) / (가능한 패턴 종류) × 가중치
- 18개 패턴 중 7개 미만 사용 시 WARN
- 18개 패턴 중 5개 이하 사용 시 FAIL → slide-curator 회귀
- 단 이전 세션과 패턴 중복 ≤ 60% (세션 간 다양성)
```

이러면 검증을 통과하기 위해 *새 패턴을 시도해야 함*. 안전한 평균 해의 함정에서 탈출.

#### 신설 축 B: lecture.md 강도 일치 (Source-Slide Strength Match)

content-quality-reviewer에 추가:

```
lecture.md의 단정 문장 = 강도 5 (강)
lecture.md의 부연 문장 = 강도 3 (중)
lecture.md의 예시 문장 = 강도 1 (약)

slide의 KeyMessage = 강도 5 매칭
slide의 Definition = 강도 4 매칭
slide의 ThreeCards = 강도 3 매칭
slide의 Comparison = 강도 4 매칭
slide의 Outro = 강도 2 매칭

매칭 편차 합 / 슬라이드 수 ≤ 0.5 → PASS
> 0.5 → WARN: 약한 콘텐츠가 강한 패턴에 매핑되었거나 그 반대
```

이러면 lecture.md의 *원래 강도*가 슬라이드에 반영됨. 문제 4 "정답 단정"의 반대 — 정답이 아닌 부분이 정답처럼 단정되는 것을 방지.

#### 신설 축 C: 세션 차별성 (Session Differentiation)

이전 세션과 비교하여:

```
이전 세션과 패턴 중복률 ≤ 60%
이전 세션과 인터랙티브 종류 중복률 ≤ 40%
이전 세션과 슬라이드 수 차이 ≥ 20%
```

이걸 plan-reviewer가 검증. 이러면 시스템 자체가 *세션 간 다양성*을 강제. 문제 5 직접 해결.

### 처방 3 (P1): history.md를 "차단 시스템"에서 "참고 시스템"으로 전환

**문제 해결**: 문제 5, 핵심 문제 2

현재 history.md는 **차단 룰 누적 시스템**입니다. 이를 다음과 같이 전환:

#### 변경 1: 차단 룰의 만료 기간 도입

```
차단 룰 lifecycle:
  추가 시점: 결함 3회 누적
  유효 기간: 다음 3개 세션
  만료 후: 자동 완화 (룰 → 권고로 전환)
  재검증: 만료 후 첫 세션에서 재발 시 다시 차단 룰로
```

이러면 차단 룰이 무한 누적되지 않음.

#### 변경 2: 세션 특성별 룰 적용

차단 룰에 *적용 조건*을 명시:

```yaml
rule: "톤 강제 차단"
applies_when:
  session_profile.tone_strength == "soft"
exempt_when:
  session_profile.tone_strength == "strong"
  AND lecture.md에 "단정" 키워드 명시
```

→ S1처럼 부드러운 세션은 톤 차단 적용, 강한 단정 필요한 세션은 면제.

#### 변경 3: 차단 룰 → 가산 룰로 일부 전환

"콘텐츠 두께 부족" 같은 경우:

- **차단 룰 (현재)**: 한 줄 desc 0건 강제 → 모든 desc가 길어짐
- **가산 룰 (제안)**: lecture.md 본문을 N% 이상 인용 시 +1점, 30% 이상 시 +3점

→ 강제하지 않되 *충실한 인용을 보상*.

### 처방 4 (P1): 검증 게이트 압축

**문제 해결**: 핵심 문제 2, 문제 5

현재 7중 검증을 3중으로 압축:

```
[현재] slide-curator → interactive-planner → visual-planner →
       layout-validator → plan-reviewer → content-quality-reviewer →
       강사 게이트 → 빌드(섹션 분할) → design-reviewer pre-build →
       design-reviewer post-build → capture-validator

[제안] slide-curator (with profile) →
       creative-reviewer (가산형 — 다양성/강도/차별성) →
       quality-reviewer (감산형 — 통합 36개 결정 + 흐름 + 두께 + 토큰) →
       강사 게이트 → 빌드 → final-validator (자동화 가능한 모든 grep 통합)
```

7개 → 4개. 그 중 1개는 *가산형*. 이렇게 하면:
- 평균 회귀 횟수 감소
- 가산형 1개가 다양성 보장
- 강사 게이트 부담 감소

단, 이건 큰 리팩터링이라 P1 (P0 후 진행).

### 처방 5 (P2): 줄바꿈 검증을 시각 폭 기반으로

**문제 해결**: 문제 2

현재 visual-planner D12는 글자 수 기반. 한글/영문/숫자/특수문자 혼합 시 부정확.

#### 변경

빌드 후 실제 렌더 폭 측정 또는 *문자별 가중치* 적용:

```
한글 = 1.0 단위
영문 대문자 = 0.7
영문 소문자 = 0.55
숫자 = 0.55
공백 = 0.3
특수문자 (마침표 등) = 0.3
```

총 *시각 폭 단위*로 임계값 적용. 또는 더 간단히 — 빌드 후 Playwright로 실제 줄 수 측정 → fail이면 회귀.

후자가 더 정확하지만 비쌈. 전자가 70% 정확도로 충분할 수 있음.

### 처방 6 (P2): wireframe을 픽셀 단위로

**문제 해결**: 문제 8

현재 visual-planner F6는 ASCII mockup. 이건 *비율*은 보이지만 *실제 픽셀*은 안 보임.

#### 변경

ASCII + 실제 SlideFrame max-width(1280px 가정) 기준 px 명시:

```
[데스크톱 1280×720]
┌─────────────────────────────────────┐  ← 1280px 폭
│ [eyebrow 200×24px]                   │
│ [title 800×96px]                     │  ← 96px 폰트, 24자 가능
│ [highlight 600×72px]                 │
│ [footer 700×24px]                    │
└─────────────────────────────────────┘
```

이걸 layout-validator가 입력으로 받아 *실제 빌드 후 pixel diff*로 검증. 또는 더 가볍게, wireframe의 px 합이 1280을 넘으면 즉시 fail.

### 처방 7 (P3): 워크플로우 문서의 스타일 정화

**문제 해결**: 문제 7

CLAUDE.md와 8개 agent .md에서:
- "§" → "Section" 또는 단순 번호 (1, 2, 3)로 교체
- "↳" → "→" 또는 "next:"로 교체
- "⛳" → 단순 텍스트 (예: "[Gate]")로 교체
- "—" → "-" 또는 ":" 사용

이러면 모델이 출력에서 같은 문자를 모방할 가능성이 줄어듭니다. design-reviewer의 grep 차단과 함께 작동하면 효과 큼.

## 부록 A: lecture.md → slide 매핑 진단 예시

S1 lecture line 32 "**첫 단정: 기능을 정하기 전에 사람과 문제를 정한다.**"의 처리 진단:

### 현재 시스템

```
1. slide-curator: H3 "기획의 정의" 안의 인용 블록으로 인식
2. KeyMessage 패턴에 매핑 결정
3. CLAUDE.md C5 검증: "기능은 답이고, 사람과 문제는 질문이다 / 질문부터 시작한다"가 정설
4. 충돌 발견 → C5 정설로 텍스트 교체 → KeyMessage message 작성
5. visual-planner D12: 글자 수 검증 → "기능은 답이고," (8자) + "사람과 문제는" (7자) + "질문이다" (4자) → message 배열 분할
6. plan-reviewer: 36개 결정 통과
7. 빌드
```

**결과**: lecture.md 원문이 시스템 정설로 *대체*. 강사가 lecture.md를 자유롭게 써도 시스템이 강제 교체.

### 처방 적용 후

```
1. session profile 확인 → S1 (tone_strength: soft)
2. lecture line 32 "첫 단정" 인식 → 강도 5 분류
3. 가산 축 B (lecture.md 강도 일치) 검증 → KeyMessage 패턴 매칭 강도 5 → 일치
4. C5 정설을 "권고"로 처리, 강사가 lecture.md에 다른 표현 쓰면 그대로 사용
5. visual-planner: 시각 폭 기반으로 자연 줄바꿈 (글자 수 X)
6. quality-reviewer: 감산 통합 검증
7. 빌드
```

**결과**: lecture.md 원문 보존. 강사 자유 표현이 그대로 슬라이드에 반영.
