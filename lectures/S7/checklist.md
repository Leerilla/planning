# 자가 점검 체크리스트

학습 종료 시점에 작업자가 본 학습을 충분히 했는지 확인한다.

---

## 영역 1: 이론 이해 점검

- [ ] 단위·통합·E2E 테스트의 차이를 한 문장으로 구분할 수 있는가
- [ ] 시나리오 통과가 동작의 진짜 정의임을 이해하는가
- [ ] 화면 떰과 시나리오 통과의 차이를 설명할 수 있는가
- [ ] Playwright MCP의 사용 흐름 4단계를 외울 수 있는가
- [ ] 자율 디버깅 3원칙(에러 그대로, 분석 먼저, 결과 검증)을 외울 수 있는가
- [ ] 무한 루프에 빠졌을 때 멈추는 명령 패턴을 알고 있는가
- [ ] 코드 단위 검증과 시나리오 단위 검증의 차이를 구분할 수 있는가
- [ ] 자료 6의 prd-reviewer와 자료 7의 scenario-verifier의 책임 분리를 설명할 수 있는가
- [ ] 검증이 단발이 아닌 루프임을 인식하는가

---

## 영역 2: 실습 산출물 점검

### 환경과 자료 6 산출물

- [ ] planning_project 폴더에서 작업 중인가
- [ ] 자료 6 산출물 5개가 모두 있는가 (화면 2개, sub-agent 2개, hook 2개 등록, PR 9개 병합)
- [ ] Playwright가 설치되어 있는가
- [ ] Playwright MCP가 연결되어 있는가
- [ ] /cost 베이스라인을 메모했는가

### 핵심 시나리오와 E2E 테스트

- [ ] PRD 핵심 시나리오 1개가 선택됐는가
- [ ] 시나리오가 사용자 흐름 처음부터 끝까지 포함하는가
- [ ] 자연어로 E2E 테스트 작성 명령을 했는가 (테스트 코드 직접 작성 X)
- [ ] e2e/ 폴더에 테스트 파일이 생성됐는가
- [ ] 테스트 실행이 시작됐는가

### 자율 디버깅

- [ ] 자율 디버깅 3원칙 명령을 사용했는가
- [ ] 에러를 요약하지 않고 풀 메시지를 그대로 전달했는가
- [ ] 분석 먼저, 수정은 그다음 순서로 명령했는가
- [ ] 수정 후 재실행으로 통과 여부를 검증했는가
- [ ] 무한 루프에 빠진 경우 정리 명령을 사용했는가
- [ ] 테스트가 통과했는가 (또는 막힘 메모가 명확한가)

### scenario-verifier sub-agent

- [ ] .claude/agents/scenario-verifier.md 파일이 작성됐는가
- [ ] frontmatter가 Agent 설계 6원칙을 따랐는가
- [ ] tools가 Read, Grep, Glob만 명시됐는가 (Write/Edit 없음)
- [ ] description에 "빌드 완료 후 호출"이 명시됐는가
- [ ] 본문에 입출력 계약이 명시됐는가
- [ ] @scenario-verifier 호출 가능한가

### 시나리오 검증 루프

- [ ] 첫 호출 보고서가 3단 구조로 출력됐는가 (통과 여부 / 막힘 지점 / 수정 제안)
- [ ] 막힘 지점 1-2개를 작업자가 직접 파일 열어 확인했는가
- [ ] 수정 제안의 적절성을 docs/prd.md와 대조했는가
- [ ] 검증 루프를 1회 이상 돌았는가 (검증 → 수정 → 재검증)
- [ ] 최종 보고서가 "통과"인가
- [ ] 작업자의 본인 검증으로 통과를 확정했는가

### 토큰 비용

- [ ] /cost 비교 결과를 메모했는가
