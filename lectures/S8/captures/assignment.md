# 과제: 공개 URL + 분석 인프라로 노출 단계 진입

## 목표

다음 학습 단계(노출과 재피드백) 시작 전까지 공개 URL이 안정적으로 동작하고 분석 도구 3종(Clarity, Sentry, 이벤트 추적)이 모두 셋업된 상태에서 다음 단계에 진입한다. 첫 사용자가 들어오는 순간부터 모든 행동·에러·가설 검증 데이터가 자동으로 수집되어야 한다.

본 단계는 *개발 지식이 필요한 단위*. 이론에서 다룬 최소 개발 어휘(HTTP·도메인·포트·환경 변수·빌드/배포·API·CORS)를 명령에 정확히 사용하는 것이 막힘을 줄이는 핵심.

---

## 산출물

### 배포

- **공개 FE URL (Vercel)**: https://{project}.vercel.app
- **공개 BE URL (Railway)**: https://{project}.up.railway.app
- 환경 변수 모두 안전하게 등록 (.gitignore에 .env*)
- CORS 화이트리스트 정책 적용 (와일드카드 X)
- 시드 6번 시나리오가 공개 URL에서 동작

### 분석 도구

- **Microsoft Clarity**: 추적 코드 삽입 + 본인 세션 1개 이상 기록
- **Sentry**: FE와 BE 모두 SDK 초기화 + 테스트 에러 도착 확인
- **이벤트 추적 3개**: 페이지 진입 / 핵심 버튼 클릭 / 핵심 기능 완료

### 의사결정 매핑

- 각 도구의 데이터가 어느 의사결정에 쓰일지 메모 (docs/analytics-plan.md)
  - Clarity → UX 개선
  - Sentry → 버그 수정
  - 이벤트 추적 → PRD 갱신

### 재피드백 메일 카피

- 다음 단계에서 사용자에게 보낼 *재피드백 요청 메일* 카피 1개

- BE와 FE 모두 공개 URL로 배포
- CORS 해결 완료 (시나리오 동작)
- Clarity, Sentry 둘 다 셋업
- 이벤트 추적 코드 1개 이상 삽입

## 권장 범위

- 이벤트 추적 3개 모두 삽입 (페이지/버튼/완료)
- 각 도구의 의사결정 매핑 메모
- 재피드백 메일 카피 작성
- 본인 세션 1개 이상 Clarity에 기록 (대시보드 확인)

---

## 자가 점검 체크리스트

- [ ] planning_project 폴더에서 작업 중인가
- [ ] BE와 FE 모두 공개 URL로 배포됐는가
- [ ] BE 코드가 process.env.PORT 사용하는가
- [ ] OPENAI_API_KEY가 Railway에만 있고 코드에 없는가
- [ ] Railway Root Directory가 server로 설정됐는가
- [ ] Vercel NEXT_PUBLIC_API_URL이 Railway URL로 등록됐는가
- [ ] CORS가 화이트리스트로 설정됐는가 (와일드카드 X)
- [ ] 공개 URL에서 시드 6번 시나리오가 동작하는가
- [ ] Clarity, Sentry, 이벤트 추적이 모두 작동하는가
- [ ] 첫 사용자가 들어오면 데이터가 자동 수집되는가
- [ ] 세 도구가 *각각 다른 질문*에 답한다는 점을 본인 말로 설명할 수 있는가

## 막혔을 때

| 시나리오 | 대응 |
| --- | --- |
| **Railway 빌드 실패 - "Cannot find module"** | server/package.json에 의존성 누락. `cd server && npm install [모듈명]` 후 재push |
| **Railway 빌드 실패 - "Port already in use" 또는 시작 안 됨** | BE 코드의 고정 포트 사용. `process.env.PORT` 사용으로 변경 명령 |
| **Railway가 잘못된 폴더 빌드** | Settings → Build → Root Directory를 `server`로 설정 |
| **Railway 무료 크레딧 소진 우려** | Settings → Usage에서 사용량 확인. 본 학습 후 결제 필요할 수 있음 |
| **Vercel 빌드 성공인데 FE에서 BE 호출 실패** | NEXT_PUBLIC_API_URL이 정확한지 확인. 환경 변수 추가 후 재배포 트리거 필요 |
| **CORS 에러가 여러 번 막힘** | 자율 디버깅 3원칙 그대로. 풀 메시지 → 분석 먼저 → 결과 검증. CORS 설정 후 Railway 재배포 대기(1-2분) |
| **환경 변수가 빌드 후 안 됨** | Vercel/Railway 환경 변수 추가 후 *재배포 트리거* 필요. 자동 안 되면 수동 redeploy |
| **Clarity 세션이 대시보드에 안 보임** | 5-10분 지연 정상. 다음 날 확인 시도. 그래도 없으면 layout.tsx에 스크립트 삽입 위치 점검 |
| **Sentry 테스트 에러가 안 옴** | DSN 정확성 확인. FE와 BE에 각각 다른 DSN 사용했는지 점검 |
| **이벤트 추적 코드 위치 모름** | scenario-verifier 활용: "PRD 핵심 가설과 매칭되는 이벤트 추적 위치 분석" 명령 |
| **NEXT_PUBLIC_*에 비밀 넣음** | 즉시 제거. NEXT_PUBLIC_은 브라우저 노출. 비밀은 Railway BE 환경 변수로 이동 |
| **GitHub에 API 키 실수 푸시** | 즉시 OpenAI 대시보드에서 키 삭제. 새 키 발급. git filter-branch로 히스토리 정리 |

## 개발 어휘 명령 양식

본 단계에서 막혔을 때 정확한 어휘를 사용하면 1회 해결 가능.

### 빌드 실패 명령 양식

```
Railway 빌드 단계에서 다음 에러가 발생합니다:

[Build Logs의 빨간 에러 풀 텍스트]

server/ 디렉토리의 코드 빌드 중 발생.
원인을 분석하고 수정 방안을 알려줘.
수정 후 git push까지 진행해줘 (Railway가 자동 재빌드).
```

### CORS 명령 양식

```
다음 CORS 에러를 분석해주세요:

[브라우저 콘솔의 에러 풀 메시지 그대로]

이 BE 코드(server/)에 CORS 설정을 추가해줘.
허용할 FE 도메인은 https://{Vercel URL}.
로컬 개발용 http://localhost:3000도 허용해줘.

설정 후 다른 도메인에서 호출 시 차단되는지도
함께 점검해줘. 수정 후 동작 확인까지 진행해줘.
```

자율 디버깅 3원칙 매핑:
- 원칙 1 (에러 그대로): "에러 풀 메시지 그대로"
- 원칙 2 (분석 먼저): "분석해주세요" 후 수정
- 원칙 3 (결과 검증): "다른 도메인 차단 확인 + 동작 확인"

## 분석 도구 셋업 표준 명령 3개

### Clarity

```
프로젝트 FE에 Microsoft Clarity 추적 코드를 삽입해줘.

Clarity 코드는 다음과 같습니다:
[추적 코드 그대로 붙여넣기]

Next.js의 src/app/layout.tsx에 삽입해서
모든 페이지에 자동 로드되도록 설정해줘.
```

### Sentry

```
프로젝트 FE와 BE에 Sentry SDK를 설치하고 초기화해줘.

Sentry DSN:
- FE: [FE DSN]
- BE: [BE DSN]

에러 발생 시 다음 컨텍스트 전송:
- 페이지 URL
- 클릭한 버튼이나 입력값 (개인정보 제외)
- BE의 경우 어느 API 엔드포인트인지
```

### 이벤트 추적

```
docs/prd.md의 핵심 시나리오에서 추적할 이벤트 3개를 결정해줘.

기준:
1. 페이지 진입 (카피 입력 화면 방문)
2. 핵심 버튼 클릭 (카피 생성)
3. 핵심 기능 완료 (카피 복사)

각 이벤트에 대해 Microsoft Clarity의 custom event 추적 코드
(window.clarity("set", "event_name", "value"))를
어디에 삽입해야 할지 분석한 뒤 코드를 추가해줘.

이벤트명은 PRD 가설과 연결 가능하게 명명.
예: copy_generation_completed
```

## 분석 도구의 의사결정 매핑

### docs/analytics-plan.md 작성 권장

다음 양식으로 본 학습 후 *어떤 데이터로 어떤 결정을 내릴 것인가* 메모.

```markdown
# 분석 도구 의사결정 매핑

## Clarity (UX 개선)
- 측정 데이터: 세션 리플레이, 히트맵, 체류 시간
- 답하는 질문: 사용자가 어디서 막히는가?
- 의사결정 영역: UX/UI 수정
- 시드 6번 적용: 키워드 5개 입력에서 머뭇거리면
  → 강제 규칙 완화 검토

## Sentry (버그 수정)
- 측정 데이터: 에러 발생 횟수, 스택 트레이스, 영향 사용자 수
- 답하는 질문: 우리가 모르는 에러가 얼마나 있는가?
- 의사결정 영역: 코드 버그 수정
- 시드 6번 적용: OpenAI timeout 5% 발생
  → retry 로직 추가 결정

## 이벤트 추적 (PRD 갱신)
- 측정 데이터: 진입 → 버튼 클릭 → 완료의 전환율
- 답하는 질문: PRD 가설이 통과하는가?
- 의사결정 영역: PRD 가설 갱신
- 시드 6번 적용: 완료율 70% 미달
  → 가설 재조정 또는 UX 수정
```

## 재피드백 메일 카피 작성 가이드

본 단계 산출물 중 *재피드백 메일 카피*는 다음 단계(노출)에서 사용.

### 카피 구조

- **어조**: "드디어 만들었습니다" 톤이 효과적
- **필수 포함**:
  - 배포 URL (Vercel)
  - 사용 시간 안내 (5-10분)
  - 응답 마감 (당일 내)
- **응답 받을 질문 3개** (변경 X):
  - "이 서비스가 출시되면 사용할 의향이 있는가" (1-5점)
  - "유료라면 월 얼마까지 낼 수 있는가"
  - "개선되면 좋을 점 1개"

### Claude Code에 카피 작성 명령

```
재피드백 요청 메일 카피 1개를 작성해줘.

대상: 셀러스쿨 카페에서 만난 시드 6번 페르소나 (1인 셀러)
어조: "드디어 만들었습니다" 톤

필수 포함:
- 배포 URL: https://{Vercel URL}
- 사용 시간: 5-10분
- 응답 마감: 당일 내
- 응답 질문 3개:
  1. 출시 시 사용 의향 (1-5점)
  2. 월 지불 의향
  3. 개선점 1개

메타 프롬프팅 패턴(이전 자료의 카피 작성 방식) 적용.
```
