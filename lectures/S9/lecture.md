# 노출과 재피드백

자료 8에서 공개 URL과 분석 인프라가 완성됐다. 본 자료는 실제 사용자에게 노출하고, 돌아온 데이터로 본인의 첫 가설을 다시 본다. 검증된 MVP는 시장이 원하는 것과 다르다. 노출은 그 거리를 처음으로 데이터로 측정하는 단계이다.

본 자료는 노출의 기획적 의미, 세 축 데이터 해석, 살아있는 페르소나로의 진화, 다음 사이클 의사결정을 다룬다. 시드 6번(1인 셀러 카피 생성기) 기준. 작업 폴더는 planning_project 그대로 사용. 본 자료는 본 학습의 마지막 단계이며 종착점은 *살아있는 페르소나로 갱신된 docs/persona.md*, *갱신된 docs/prd.md*, *본인 다음 단계 결정 1개*이다.

학습 목표:

- 검증된 MVP와 시장이 원하는 것의 차이를 한 문장으로 설명한다
- 세 축 데이터(응답·Clarity·Sentry·이벤트 추적)에서 신호와 잡음을 구분한다
- 페르소나 3단계 진화(가설 → 검증된 → 살아있는)의 마지막 단계로 갱신한다
- 다음 사이클 결정 3 갈래(Pivot · Persevere · Kill)를 본인 데이터로 적용한다
- 16시간 + 5시간 학습 사이클을 한 바퀴 닫고 다음 단계 결정을 손에 쥔다

## 이론

### 1️⃣ 노출의 기획적 의미

이 챕터를 학습한 뒤 다음을 할 수 있다.

- 검증된 MVP와 시장의 거리를 인식한다
- 두 축 안전망이 본 단계에서 어떻게 재활용되는지 안다
- 노출 카피와 첫 검증 카피의 톤 차이를 구분한다

#### 노출의 정의

노출(Exposure)은 **검증된 MVP를 실제 사용자에게 공개하고 데이터를 수집하는 단계**이다.

자료 1부터 자료 8까지 작업자가 만든 모든 것은 *본인이 옳다고 믿은 것*이다. 페르소나도 본인이 그렸고, 가설도 본인이 세웠고, MVP도 본인이 검증된 페인포인트 위에서 만들었다.

::: aside
자료 2의 능동·수동 검증을 거쳤고, 자료 3의 NotebookLM으로 출처를 확인했고, 자료 7의 scenario-verifier로 시나리오 통과를 확인했다. 그러나 이 모든 검증은 작업자가 직접 만나거나 분석한 데이터 위에서 일어났다.
:::

#### 첫 단정

> **검증된 MVP는 시장이 원하는 것과 다르다.**
> 

자료 1의 *"첫 가설이 그대로 살아남는 비율은 평균 30% 미만"*이라는 통계와 직접 연결된다. 본 단계의 데이터가 그 차이를 처음으로 가시화한다.

#### 노출의 본질

노출은 작업자의 믿음을 시험하는 단계가 아니라 **작업자의 모름을 발견하는 단계**이다.

| 발견 | 결과 |
| --- | --- |
| 모름이 발견됨 | 갱신할 페르소나와 PRD가 있음 |
| 모름이 발견 안 됨 | 5 Whys가 충분히 깊지 못했거나 페르소나가 너무 좁음 |

::: aside
차이가 크다고 실패가 아니다. 차이를 *측정*했다는 사실이 다음 사이클의 출발점이 된다.
:::

#### 두 축 안전망의 재활용

자료 2에서 도입한 두 축 안전망이 본 단계에서 다시 작동한다.

| 비교 | 자료 2 두 축 | 본 단계 두 축 |
| --- | --- | --- |
| **능동** | 콜드 메일 카피로 인터뷰 요청 | 재피드백 메일로 사용 후기 요청 |
| **수동** | Playwright MCP로 커뮤니티 글 스크래핑 | 분석 도구 3종이 자동 수집 |
| **데이터 본질** | *문제가 진짜인가* 측정 | *MVP가 문제를 푸는가* 측정 |

응답률 5-15% 현실은 본 단계에서도 같다. 컨택 10명에 보내면 응답 1-2명 기대.

#### 응답 0건이어도 진입 가능

> **응답이 0건이어도 분석 도구의 데이터가 다음 사이클 결정의 입력이 된다.**
> 

```
❌ "응답이 0건이라 다음 단계로 못 갑니다"
   → 한 축 의존
✅ "능동 응답 0건이어도 Clarity 세션으로 분석 진입"
   → 두 축 안전망의 재활용
```

#### 노출 카피의 톤 차이

자료 8 과제로 준비된 재피드백 메일 카피는 **"드디어 만들었습니다"** 톤이다.

| 비교 | 자료 2 콜드 메일 | 본 단계 재피드백 메일 |
| --- | --- | --- |
| **목적** | 페인포인트 확인 | 솔루션 검증 |
| **질문** | "이런 문제를 겪고 계신가요?" | "이런 문제를 풀어봤는데 진짜 풀렸나요?" |
| **응답률** | 5-15% | 자료 2 응답자에게 보내면 더 높음 |

::: aside
자료 2에서 인터뷰에 응답한 1-3명이 본 단계의 1차 발송 대상이 된다. 한 번 답해준 사람에게 결과물을 보여주는 것이 응답률이 가장 높다.
:::

| 용어 | 정의 |
| --- | --- |
| 노출 | 검증된 MVP를 실제 사용자에게 공개하고 데이터를 수집하는 단계 |
| 재피드백 | 자료 2 첫 검증에 이어 솔루션 동작 후의 두 번째 검증 |
| 거리 측정 | 작업자의 믿음과 시장 반응 사이의 차이를 데이터로 확인 |
| 두 축 안전망 | 능동(재피드백 메일) + 수동(분석 도구) |

### 2️⃣ 세 축 데이터 해석

이 챕터를 학습한 뒤 다음을 할 수 있다.

- 신호와 잡음을 30% 기준 또는 3-5건 기준으로 구분한다
- 네 종류 데이터(응답·Clarity·Sentry·이벤트 추적)의 역할 차이를 안다
- NotebookLM 재오픈으로 교차 분석한다

#### 1명의 행동은 신호가 아니다

데이터 해석에서 가장 흔한 실수는 **1명의 행동을 시장의 신호로 착각**하는 것이다.

```
❌ 한 사용자가 키워드 입력에서 막힘
   → 입력 방식 즉시 변경
✅ 10명 중 7명이 같은 자리에서 막힘
   → 신호 확인 후 변경
```

#### 두 번째 단정

> **한 사용자의 한 행동은 신호가 아니다. 패턴이 신호다.**
> 

#### 신호 판단 기준

| 기준 | 적용 |
| --- | --- |
| **30% 이상** | 사용자의 30% 이상에서 반복되면 신호 |
| **3건 미만** | 단발 행동은 잡음으로 분류, 메모만 |
| **본 학습 현실** | 10-30명 수준에서는 3-5명 같은 행동도 신호로 봄 |

::: aside
30%는 절대적 기준이 아니라 작업자의 판단 가이드. 사용자 수가 적은 본 학습에서는 절대 수치도 함께 본다.
:::

#### 네 종류 데이터의 역할 차이

본 단계에서 마주하는 데이터는 네 종류이다. 자료 8의 분석 도구 3종과 자료 2의 능동 응답.

| 데이터 | 답하는 질문 | 본 단계 의사결정 |
| --- | --- | --- |
| **응답** | 페르소나가 *무엇을 느꼈는가* | 페르소나 갱신, PRD 일부 수정 |
| **Clarity** | 페르소나가 *어디서 막혔는가* | UX 개선 |
| **Sentry** | *우리가 모르는 에러가 얼마나 있는가* | 버그 수정 |
| **이벤트 추적** | *PRD 가설이 통과했는가* | PRD 갱신 또는 Pivot |

네 종류가 *서로 다른 질문에 답한다*. 한 데이터로 모든 결정을 내리지 않는다.

#### 응답의 특징

응답(능동 데이터)은 페르소나의 **말**을 모은다.

```
✅ 깊이 있음 (후속 질문 가능)
❌ 편향 큼 (응답자는 가장 적극적인 사용자)
```

::: aside
응답을 *시장 전체의 의견*으로 받아들이면 안 된다. 깊은 한 사례로 본다.
:::

#### Clarity의 특징

Clarity(수동·행동 데이터)는 페르소나의 **행동**을 모은다.

```
✅ 폭이 넓고 편향 적음
✅ 세션 리플레이로 영상 재생
❌ "왜 그렇게 행동했는지" 추측만 가능
```

#### Sentry의 특징

Sentry(수동·에러 데이터)는 **사용자가 알려주지 않은 에러**를 자동 수집한다.

```
[사용자 신뢰 침식의 안전망]
- 사용자는 에러 만나도 안 알려줌
- 그냥 떠남
- Sentry가 자동 수집 → 작업자에게 알림
```

::: aside
5%의 사용자가 timeout을 만났다는 사실을 Sentry가 알려주지 않으면 영원히 모른다.
:::

#### 이벤트 추적의 특징

이벤트 추적(수동·가설 데이터)은 PRD 가설의 **통과율을 숫자로 측정**한다.

```
페이지 진입 N명
       ↓ (전환율 M/N)
핵심 버튼 클릭 M명
       ↓ (전환율 K/M)
핵심 기능 완료 K명
       ↓
전체 완료율 K/N
       ↓
PRD 가설 통과 여부 결정
```

#### NotebookLM 재오픈

자료 3에서 만든 NotebookLM 노트북이 본 단계에서 다시 사용된다.

```
[자료 3 노트북에 추가 자료 업로드]
- 응답 정리 메모
- Clarity 세션 메모
- Sentry 에러 요약
- 이벤트 추적 전환율 데이터
       ↓
[네 종류 데이터를 한 컨텍스트에서 분석]
       ↓
교차 질문 가능:
- 응답 패턴이 행동 데이터에서도 보이는가?
- PRD 가설 미통과가 어떤 에러와 연결되는가?
```

::: aside
자료 3의 노트북이 21시간 후에 다시 살아난다. 학습의 누적 구조가 본 단계에서 체감된다.
:::

#### 안티패턴 vs 종합 해석

```
❌ "응답 1명이 좋다고 했으니 PRD 통과"
   → 1명을 시장으로 착각

✅ "응답 1명 + Clarity 5건 + 완료율 60%를
    NotebookLM에서 함께 본 뒤 패턴 추출"
   → 네 종류 데이터의 종합 해석
```

#### 2️⃣ 챕터 용어 해설

| 용어 | 정의 |
| --- | --- |
| 신호와 잡음 | 패턴은 신호, 단발 행동은 잡음 |
| 30% 기준 | 사용자의 30% 이상에서 반복되면 신호로 간주 |
| 네 종류 데이터 | 응답·Clarity·Sentry·이벤트 추적 |
| NotebookLM 재오픈 | 자료 3 노트북에 본 단계 데이터를 추가해 교차 분석 |

### 3️⃣ 살아있는 페르소나로 진화

이 챕터를 학습한 뒤 다음을 할 수 있다.

- 페르소나 3단계 진화의 마지막 단계를 인식한다
- 페르소나 갱신의 두 종류 변화(추가·제거)를 적용한다
- docs/persona.md와 docs/prd.md를 동시 갱신한다

#### 페르소나 3단계 진화

자료 1에서 명시적으로 도입했던 페르소나 3단계 진화의 마지막 단계가 본 단계에서 시작된다.

| 단계 | 어디서 만들어졌나 | 입력 데이터 |
| --- | --- | --- |
| 1. 가설 페르소나 | 자료 1 | 직관 + 1차 리서치 |
| 2. 검증된 페르소나 | 자료 2-3 | 인터뷰 + NotebookLM |
| **3. 살아있는 페르소나** | **본 단계** | **실제 사용 + 재피드백** |

#### 세 번째 단정

> **본 단계가 두 번째에서 세 번째로 가는 다리다.**
> 

#### 시드 6번 3단계 예시

사례: 시드 6번 페르소나의 3단계 진화.

```
[가설 페르소나, 자료 1]
"월 매출 100-500만원 1인 스마트스토어 셀러"
→ 직군과 환경 가설. 페인포인트 검증 전.

[검증된 페르소나, 자료 2-3]
"월 매출 100-500만원 1인 셀러 중
 카피 작성에 1-2시간 쓰는 사람"
→ 페인포인트 실재 확인. MVP 사용은 아직 모름.

[살아있는 페르소나, 본 단계]
"월 매출 100-500만원 1인 셀러 중
 카피 작성에 1-2시간 쓰고,
 키워드 5개 입력에서 평균 3개만 입력하는 사람.
 AI 자동 생성보다 키워드 제안 + 본인 작성 선호."
→ 본인의 가설에서 일부 추가, 일부 제거.
```

#### 페르소나 갱신의 두 종류 변화

페르소나 갱신은 두 종류의 변화를 만든다.

| 변화 | 의미 | 시드 6번 예시 |
| --- | --- | --- |
| **추가** | 본인이 몰랐던 특성이 데이터로 드러남 | 키워드 5개 중 평균 3개만 입력 (Clarity에서 발견) |
| **제거** | 가설에 적었지만 데이터에서 안 보임 | 광고비 의존도 (응답에서 시간 절약만 강조됨) |

::: aside
두 변화가 동시에 일어나면 페르소나가 *살아있는* 상태가 된다. 살아있다는 것은 *실제 사용 데이터로 계속 갱신될 수 있는 상태*이다.
:::

#### docs/persona.md와 docs/prd.md 동시 갱신

페르소나 갱신은 PRD 갱신을 동반한다.

```
[페르소나 갱신]
키워드 5개 → 키워드 3-5개 가변 입력
       ↓
[PRD 핵심 기능 갱신]
"키워드 5개 입력" → "키워드 3-5개 가변 입력"

[페르소나 제거]
광고비 의존도 동기 제거
       ↓
[PRD 성공 지표 갱신]
광고 관련 항목 제거
```

#### 자동 커밋의 갱신 근거

자료 6의 git-committer sub-agent가 자동으로 커밋한다.

```
[자동 커밋 메시지 예시]
refactor: persona·prd 갱신 — Clarity 데이터 기반
 키워드 가변 입력으로 변경

[근거 명시]
- Clarity 세션 8건 중 6건이 키워드 3개만 입력
- 응답 2건이 "5개는 부담"으로 언급
```

::: aside
작업자가 갱신의 근거를 데이터로 명시한 커밋이 GitHub에 남는다.
:::

#### 안티패턴 vs 30% 기준 적용

```
❌ "1명 응답에서 나온 의견을 페르소나에 추가"
   → 잡음을 신호로 착각

✅ "Clarity 30%+ 또는 응답 다수에서 같은 패턴이
    보일 때만 페르소나에 반영"
   → 30% 기준의 일관 적용
```

#### 페르소나 3단계 비교

| 비교 | 가설 페르소나 | 검증된 페르소나 | 살아있는 페르소나 |
| --- | --- | --- | --- |
| **시점** | 자료 1 | 자료 2-3 | 본 단계 |
| **자신감** | 낮음 (가설) | 중간 (검증) | 높음 (사용 데이터) |
| **갱신** | 검증 단계 | 노출 단계 | 다음 사이클 |

#### 3️⃣ 챕터 용어 해설

| 용어 | 정의 |
| --- | --- |
| 살아있는 페르소나 | 실제 사용 데이터로 갱신된 페르소나. 계속 갱신될 수 있는 상태 |
| 갱신의 두 종류 | 추가(몰랐던 특성)와 제거(데이터에서 안 보이는 특성) |
| PRD 동시 갱신 | 페르소나 갱신이 PRD의 핵심 기능과 성공 지표 갱신을 동반 |
| 30% 기준 | 페르소나에 반영할지의 판단 기준 |

### 4️⃣ 다음 사이클 결정과 학습 종합

이 챕터를 학습한 뒤 다음을 할 수 있다.

- 학습 종료와 빌드 종료의 차이를 인식한다
- 3 갈래 결정(Pivot · Persevere · Kill)을 데이터 신호로 적용한다
- 5단계 사슬의 약한 고리를 본인 데이터로 인식한다

#### 학습 종료 ≠ 빌드 종료

본 학습은 21시간(16시간 + 5시간)의 한 사이클이다. 본 단계가 끝나면 학습은 종료되지만 작업자의 빌드는 이어진다.

#### 네 번째 단정

> **학습 종착점은 다음 결정을 손에 쥐는 것이다.**
> 

```
[결정 없이 끝나는 경우]
작업자는 다음 사이클에서 어디서부터 시작할지 모름
→ 멈춤

[결정을 쥐고 끝나는 경우]
1주 안에 할 일 1개 + 1개월 안에 할 일 1개 명확
→ 다음 사이클의 첫 걸음
```

#### 3 갈래 의사결정

다음 사이클 결정은 세 갈래이다.

| 결정 | 의미 |
| --- | --- |
| **Pivot** | 페르소나 또는 핵심 가설을 바꿈 |
| **Persevere** | PRD 일부만 갱신, 같은 방향 유지 |
| **Kill** | 본 시드 폐기, 다른 시드로 이동 |

::: aside
린스타트업의 표준 용어이지만 본 학습의 데이터 위에서 본인 판단으로 적용한다.
:::

#### Pivot의 신호

같은 시드를 유지하지만 *누구를 위한 무엇*의 정의가 바뀐다.

```
[Pivot 신호]
- 이벤트 추적 완료율 30% 미만
- Clarity에서 다른 페르소나가 들어옴
- 응답에서 "다른 문제"가 더 강조됨

[시드 6번 Pivot 예시]
"1인 셀러" → "주 매출 100만원 미만 부업 셀러"
"카피 생성" → "키워드 추천"
```

#### Persevere의 신호

페르소나 큰 윤곽 유지, UX 개선과 일부 기능 수정.

```
[Persevere 신호]
- 완료율 50-70%
- Clarity가 명확한 UX 막힘 1-2개 보여줌
- 응답이 "방향은 맞지만 개선점"을 알려줌

[데이터 해석]
방향은 맞지만 실행에 빈틈이 있음
```

#### Kill의 신호

본 시드 폐기, 다음 시드로 이동.

```
[Kill 신호]
- 응답률 0%
- 사용 세션 매우 적음 (5건 미만)
- 완료율 매우 낮음
- 페르소나 실재 미확인

[데이터 해석]
"이 페르소나는 이 솔루션을 원하지 않는다"
```

::: aside
Kill 결정이 가장 어렵다. 21시간을 들였는데 폐기 결정은 심리적으로 무겁다.
:::

#### Kill이 빠른 실패

자료 1의 단정이 본 단계에서 적용된다.

> **잘못된 가설을 빨리 검증하면 빨리 실패할 뿐이다. — 자료 1**
> 

빨리 실패하고 다음 시드로 가는 것이 5단계 사슬을 한 번 더 도는 것이다.

#### 안티패턴 vs 데이터 기반 결정

```
❌ "21시간 들였으니 Persevere"
   → 매몰비용에 의한 결정

✅ "데이터 신호로 Pivot이 맞으면 Pivot,
    Kill이 맞으면 Kill"
   → 데이터 기반 의사결정
```

#### 학습 회고 3개 질문

본 단계 마지막 30분은 학습 전체의 회고이다.

```
질문 1: 5단계 사슬 중 가장 약했던 단계는?
       → 다음 사이클의 강화 대상

질문 2: AI 도구 중 가장 가치 있었던 것과
       가장 어려웠던 것은?
       → 본인 사이클의 도구 선택 기준

질문 3: 학습 종료 후 본인이 다음에 할 일은?
       → 학습의 진짜 종착점
```

::: aside
질문 3의 답이 학습 종착점이다. 결정 없이 끝나면 학습이 종료된 것이 아니다.
:::

#### 4️⃣ 챕터 용어 해설

| 용어 | 정의 |
| --- | --- |
| Pivot | 페르소나 또는 핵심 가설을 바꾸는 결정 |
| Persevere | PRD 일부만 갱신하고 같은 방향으로 빌드 |
| Kill | 본 시드를 폐기하고 다른 시드로 이동 |
| 5단계 사슬의 약한 고리 | 본 학습에서 가장 약했던 단계 |

## 실습

본 실습의 모든 예시는 시드 6번(1인 셀러 상품 상세페이지 카피 생성기) 기준이다.

#### 3-5. 분석 메모 정리

## ⭐ Tips: 함정과 처방

- **1명의 행동은 신호가 아니다** — 30% 기준 또는 3-5건 기준으로 신호와 잡음을 구분한다. 1-2건은 잡음으로 분류하고 메모만.
- **응답률 5-15%는 본 단계에서도 같다** — 10명 발송에 1-2명 응답 기대. 응답 0건이어도 분석 도구 데이터로 다음 사이클 결정 가능.
- **Kill 결정이 가장 어렵다** — 21시간 들였으니 Persevere로 가고 싶은 매몰비용의 함정. 데이터가 Kill을 가리키면 Kill을 내린다.
- **페르소나 갱신은 추가와 제거 두 종류** — 본인이 몰랐던 특성을 추가하고, 가설이었지만 데이터에서 안 보인 특성을 제거.
- **NotebookLM 재오픈으로 교차 분석** — 자료 3 노트북에 응답·Clarity·Sentry·이벤트 데이터를 추가 업로드. 한 컨텍스트에서 분석.
- **자동 커밋 메시지에 갱신 근거 명시** — git-committer가 데이터 근거를 메시지에 넣는다. 갱신 이유가 git log에 남는다.
- **학습 종착점은 결정 1개** — 결정 없이 끝나면 학습이 종료된 것이 아니다. Pivot · Persevere · Kill 중 본인 결정 1개.
- **5단계 사슬의 약한 고리를 인식한다** — 본 학습에서 가장 약했던 단계가 다음 사이클의 강화 대상이다.
- **21시간 사이클은 단축 가능** — 두 번째 사이클부터 짧아진다. 메타 프롬프팅·위임 3원칙·검증 우선주의는 본 학습 후의 모든 프로젝트에 재사용.
- **검증 우선주의의 마지막 적용** — AI가 추천한 Pivot · Persevere · Kill 결정을 그대로 받아들이지 않는다. 작업자가 직접 데이터를 보고 본인 판단.
