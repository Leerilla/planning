# 과제: 살아있는 페르소나 + 다음 사이클 결정으로 학습 종료

## 목표

본 학습의 마지막 과제이다. 21시간(16시간 + 5시간) 학습 사이클을 한 바퀴 닫고, 본인 다음 단계 결정 1개를 손에 쥔 상태로 학습을 종료한다. 살아있는 페르소나로 갱신된 docs/persona.md, 갱신된 docs/prd.md, 다음 사이클 결정 메모, 그리고 학습 전체 회고가 본 과제의 핵심 산출물이다.

본 단계는 *결정이 없으면 학습이 종료된 것이 아닌* 단계이다. 추상적인 *"본인 빌드를 계속한다"*가 아니라 *"1주 안에 인터뷰 3명 추가 신청"* 같은 구체 행동이 다음 사이클의 첫 걸음이 된다.

## 산출물

### 노출 운영

- **발송 메모**: 발송 시각, 대상 수, 채널별 발송, 응답 기대 수 (Step 1 산출물)
- **재피드백 메일 발송 완료**: 10명 이상에게 발송. 자료 8 과제의 카피 사용
- **추가 커뮤니티 스크래핑**: 새로운 페르소나 채널 1-2곳의 CSV 30건 이상

### 데이터 해석

- **분석 메모**: Clarity 세션 분석, Sentry 에러 패턴, 이벤트 추적 전환율 (Step 3 산출물)
- **종합 분석 메모**: NotebookLM에서 네 종류 데이터 교차 분석 결과 (Step 4 산출물)
- **인용 검증 메모**: NotebookLM 답변의 인용 1-2개 직접 확인 결과

### 페르소나·PRD 갱신

- **갱신된 docs/persona.md**: 30% 기준으로 추가·제거 변화 반영. 살아있는 페르소나 상태
- **갱신된 docs/prd.md**: 5요소 모두 데이터 기반으로 갱신
- **자동 커밋**: git-committer가 갱신 근거를 명시한 커밋 메시지 작성

### 다음 사이클 결정

- **결정 메모 (docs/next-cycle.md)**: Pivot · Persevere · Kill 중 결정 1개 + 근거 데이터 3개 이상
- **1주 안 행동 1개**: 학습 종료 후 일주일 안에 할 구체적 행동
- **1개월 안 행동 1개**: 다음 사이클 시작 시점

### 학습 회고

- **5단계 사슬 약한 고리 인식**: 본 학습에서 가장 약했던 단계 명시
- **AI 도구 평가**: 가장 가치 있었던 것 + 가장 어려웠던 것
- **본인 사이클 첫 걸음**: 학습 종료 후 본인이 다음에 할 일 1개

## 막혔을 때

| 시나리오 | 대응 |
| --- | --- |
| **응답이 0건이다** | 두 축 안전망 작동. 분석 도구 데이터(Clarity, Sentry, 이벤트 추적)로 진행. Step 3-4 그대로 수행 |
| **Clarity 세션이 1-2건뿐이다** | 정상 (셋업 직후 5-10분 지연). 본인 세션 + 들어온 1-2건을 영상으로 보고, *개별 사례*로 기록. 학습 종료 후 1주일간 데이터 추가됨 |
| **NotebookLM이 자료 3 노트북을 못 찾는다** | notebooklm.google.com 접속 후 본인 노트북 목록 확인. 새 노트북 생성 후 자료 3 자료 재업로드도 가능 |
| **이벤트 추적 데이터가 0이다** | 자료 8의 이벤트 추적 코드 삽입 위치 점검. layout.tsx의 Clarity 스크립트가 모든 페이지에 로드되는지 확인. window.clarity 함수가 정의됐는지 콘솔에서 확인 |
| **자동 커밋이 일어나지 않는다** | 자료 6의 Stop hook 작동 점검. settings.json의 hooks 설정 확인. git-committer.md의 description에 "응답 종료 시 호출" 있는지 |
| **Pivot · Persevere · Kill 결정이 안 내려진다** | 데이터가 모호하면 *보류*가 답이 아니라 *현재까지 데이터로 잠정 결정*이 답. 1주일 후 추가 데이터로 갱신 가능하다고 메모하고 결정 진행 |
| **페르소나 갱신 변화가 너무 작거나 너무 크다** | 너무 작음 → 5 Whys로 데이터를 더 깊이 본다. 너무 큼 → Pivot 신호일 수 있음. Step 6에서 본격 판단 |
| **응답 1명이 부정적인 의견이라 좌절** | 1명은 신호가 아니다. 30% 기준 또는 3-5건 기준으로 다시 본다. 1명의 부정 의견은 메모만, 페르소나 갱신에는 반영 X |
| **학습 종료 후 무엇을 해야 할지 모르겠다** | 다음 사이클 결정 메모의 *1주 안 행동 1개*를 다시 본다. 구체적이지 않으면 다시 구체화. 추상적 "본인 빌드 계속" X |
| **시드 6번이 아닌 본인 시드를 적용했을 때 데이터 부족** | 본인 페르소나의 검증 가능 채널이 좁을 가능성. 자료 1 페르소나 워크시트의 검증 가능 채널을 확장 후 발송 |

### 종합 분석 명령 양식

```
이 노트북의 모든 자료를 종합해서 다음을 분석해줘:

[입력 데이터]
- 응답 N건 (Step 2)
- Clarity 세션 N건 (Step 3)
- Sentry 에러 N건 (Step 3)
- 이벤트 추적 전환율 (Step 3)
- 추가 커뮤니티 스크래핑 (Step 2)

[분석 질문]
1. 응답 페인포인트와 Clarity 행동 데이터가 같은 부분을 가리키는가?
2. PRD 가설이 이벤트 추적 전환율에서 통과했는가?
3. Sentry 에러 패턴과 응답 불만이 같은 부분인가?
4. 페르소나 가설과 다른 페르소나가 들어온 흔적이 있는가?

각 답변에 인용 번호 표시.
```

- 원칙 1 (에러 그대로): 데이터를 그대로 입력
- 원칙 2 (분석 먼저): "분석해줘" 후 결정
- 원칙 3 (결과 검증): 인용 클릭으로 직접 확인

## 학습 종료의 정서적 운영

본 학습은 21시간의 한 사이클이다. 종료 시점에 *학습이 끝났다*는 안도감과 *내가 무엇을 얻었는가*에 대한 회의가 동시에 일어날 수 있다. 다음 자세가 권장된다.

- **결정 1개를 손에 쥐었으면 충분하다**: 완벽한 산출물이 아니라 *다음 사이클의 첫 걸음*이 학습 종착점이다.
- **빨리 실패하는 것은 가치 있다**: Kill 결정도 의미 있는 결과이다. 21시간으로 시드가 안 되는 것을 확인한 것이 다음 시드의 시간을 절약한다.
- **본 학습은 시작이지 끝이 아니다**: 메타 프롬프팅·위임 3원칙·NotebookLM·sub-agent는 본 학습 후의 모든 프로젝트에 재사용된다. 본 학습의 가치는 종료 후에 발현된다.

## 마감

학습 종료 시점 (본 단계가 마지막).

본 과제 종료 후 본 학습 전체가 종료된다. 작업자의 본인 사이클은 학습 종료 후 본인 페이스로 진행된다.

**산출물의 완성도가 100%가 아니어도 된다.** 최소 인정 범위 + 자가 점검 체크리스트 통과가 합격선이다. 다만 *다음 사이클 결정 1개*는 반드시 손에 쥐고 끝낸다. 결정 없이 끝나면 학습이 종료된 것이 아니다.
