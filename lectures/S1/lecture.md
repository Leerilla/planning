# 기획의 본질과 문제 발견

기획은 누구의 어떤 문제를 어떻게 풀 것인가의 답을 정의하는 일이다. 좋은 기획은 페르소나에서 출발해 검증 가능한 가설을 만들고, 나쁜 기획은 기능에서 출발해 검증 불가능한 욕망을 만든다. AI는 기획의 속도를 바꾸지만 기획의 품질을 대신 만들어주지는 않는다.

본 자료는 기획의 본질과 5단계 프레임, AI 시대 기획의 변화, 그리고 출처 검증의 실전을 다룬다. 자료의 종착점은 **고객을 만나기 직전의 1차 가설을 손에 쥐는 것**이며, 그 이후의 실제 검증은 다음 단계 자료에서 다룬다.

**학습 목표**

- 좋은 기획과 나쁜 기획을 한 문장으로 구분한다
- 기획 5단계(문제, 페르소나, 가설, 검증, 정제)에서 작업자의 위치를 식별한다
- 문제를 5 Whys로 한 단계 더 깊게 파고든다
- AI가 만든 리서치의 출처를 직접 클릭해 검증한다
- 1차 가설(문제, 페르소나, 핵심 가설 3개)을 워크시트에 작성한다

## 이론

### 1️⃣ 기획이란 무엇인가

이 챕터를 학습한 뒤 다음을 할 수 있다.

- 좋은 기획과 나쁜 기획을 한 문장으로 구분한다
- 문제를 5 Whys로 한 단계 더 깊게 파고든다
- 가설 페르소나의 의미와 위치를 이해한다

#### 기획의 정의

기획(Planning)은 **누구의 어떤 문제를 어떻게 풀 것인가**의 답을 정의하는 일이다.

세 질문 중 하나라도 모호하면 기획이 아니다.

::: aside
"쇼핑몰을 만들고 싶다", "AI로 멋진 것을 만들고 싶다"는 누구·문제·방법 어느 것도 답하지 않는다. 그것은 욕망이지 기획이 아니다. 강사는 이 지점에서 작업자에게 본인 아이디어가 세 칸 중 몇 칸이 채워졌는지 직접 점검하게 한다.
:::

---

세 개의 핵심 질문이 모두 채워져야 기획이 성립한다.

- **누구**(페르소나, Persona): 서비스가 풀려는 문제를 가진 구체적 사용자
- **어떤 문제**(페인포인트, Pain Point): 페르소나가 실제로 겪는 불편과 어려움
- **어떻게**(솔루션, Solution): 핵심 기능과 작동 방식

```
❌ "30대 직장인"        → 너무 넓음, 검증 불가
✅ "5-30인 스타트업 PM"  → 좁고 구체적, 검증 가능
```

::: aside
첫 한 줄을 이 세 질문 양식에 강제로 끼워 넣어 본다. 끼워지지 않으면 욕망이고, 끼워졌더라도 한 칸이 모호하면 그 칸을 더 좁힌다. 좁히는 것은 페르소나의 수를 줄이는 것이 아니라 페르소나의 윤곽을 명확하게 만드는 일이다.
:::

#### 좋은 기획 vs 나쁜 기획

| 구분 | 좋은 기획 | 나쁜 기획 |
| --- | --- | --- |
| **출발점** | 페르소나 | 기능 |
| **검증 가능성** | 가능 | 불가능 |
| **묻는 질문** | "이 페인포인트가 진짜인가" | "이 도구가 마음에 드는가" |
| **실패 시점** | 만들기 전 | 만든 후 |

**출발점이 검증 가능성을 결정한다.** 페르소나에서 출발하면 가설의 진위가 데이터로 돌아온다. 기능에서 출발한 기획은 만들기 전에는 누구도 답을 모르고, 만든 뒤에 답이 좋지 않으면 처음으로 돌아가야 한다.

#### 첫 단정

> **기능을 정하기 전에 사람과 문제를 정한다.**
> 

이 차이가 노출 단계에서 누구에게 무엇을 물을지를 결정한다. 페르소나 기반 작업자는 답변자에게 "이 페인포인트가 진짜였는가"를 명확하게 물을 수 있다. 기능 기반 작업자는 "이 도구가 마음에 드는가" 같은 모호한 질문밖에 던지지 못한다.

::: aside
답변자가 "괜찮네요"라고 해도 그게 페인포인트 해결인지 단순한 호의인지 구분되지 않는다. 강사는 이 점을 강조해 "사용자 인터뷰는 페르소나가 먼저"라는 원칙을 각인시킨다.
:::

---

사례: 안티패턴 vs 올바른 출발

```
❌ 안티패턴
"쇼핑몰을 만들고 싶어요. 기능부터 정해봅시다"
→ 누구를 위한 쇼핑몰인지 모름
→ 어떤 문제를 푸는지 모름
→ 검증할 가설이 없음

✅ 올바른 출발
"5-30인 스타트업의 PM이 줌 회의 후 액션아이템 정리에
30분 이상 걸린다는 문제부터 정한다"
→ 페르소나·문제·상황 셋이 한 문장에 들어감
```

페르소나·문제·상황 셋이 한 문장에 들어가야 출발이 된다.

### 문제는 한 번에 정의되지 않는다

첫 문제 진술은 대부분 **증상**에서 멈춘다.

"회의록 정리에 시간이 많이 든다"는 증상이지 문제가 아니다. 진짜 문제를 찾으려면 "왜?"를 최소 3-5번 더 물어야 한다.

::: aside
진짜 문제일수록 페르소나가 좁아지고 가설이 검증 가능해진다. 한 번에 진짜 문제에 도달하는 작업자는 없다. 첫 진술을 의심하는 습관이 있을 뿐이다. 강사는 작업자가 5 Whys에서 막히는 지점을 그대로 메모하게 한다 — 막힘 자체가 정보다.
:::

---

사례: 5 Whys를 회의록 문제에 적용해보자.

```
[증상] 회의록 정리에 시간이 많이 든다
   ↓ 왜?
[1] 발언을 다 받아쓰지 못해 영상을 다시 본다
   ↓ 왜?
[2] 회의 중 다음 안건을 진행하느라 받아쓸 여유가 없다
   ↓ 왜?
[3] 액션아이템과 결정사항을 그 자리에서 분류해야 한다
   ↓ 왜?
[4] 액션아이템 누락이 다음 주 진행을 막는다
   ↓ 왜?
[5] 누락된 아이템 재합의에 별도 회의가 필요하다
```

**결론**: 진짜 문제는 "정리 시간"이 아니라 **"액션아이템 누락이 만드는 재합의 비용"**이다.

#### 기획 5단계 프레임

기획은 다음 5단계를 거친다. **한 단계의 출력이 다음 단계의 입력이 된다.**

1. **문제(Problem)** — 한 문장의 페인포인트 (5 Whys로 깊이 파기)
2. **페르소나(Persona)** — 6줄짜리 가설 페르소나
3. **가설(Hypothesis)** — 검증 가능한 가설 3개
4. **검증(Validation)** — 능동·수동 두 축의 데이터
5. **정제(Refinement)** — PRD + 기능명세 + 와이어프레임

사슬은 가장 약한 고리에서 끊어진다. 한 단계라도 흐릿하게 두면 그 약한 고리가 전체 결과를 결정한다.

::: aside
본 자료에서 손에 쥐는 것은 1·2·3단계의 1차 가설이다. 완성이 아니라 출발이다. 4-5단계는 다음 자료에서 다룬다. 강사는 작업자가 4-5단계를 미리 걱정하지 않도록 "이 자리에선 3단계까지만"이라고 분명히 한다.
:::

---

> **1차 가설은 검증 대상이지 정답이 아니다.**
> 

첫 가설이 그대로 살아남는 비율은 평균 **30% 미만**이다. 검증 결과 가설이 틀렸다면 그것은 실패가 아니라 학습이다.

```
❌ "확실한 것만 적자"  → 가설 작성을 가장 많이 막는 함정
✅ "30%만 맞아도 충분"  → 1차 가설의 올바른 자세
```

#### 페르소나의 3단계 진화

페르소나는 한 번 만들고 끝나는 산출물이 아니다. 단계별로 다른 깊이로 도출되고 진화한다.

1. **가설 페르소나(Proto-persona)** — 데이터 없이 직관과 1차 리서치로 만든 첫 윤곽 *← 본 자료*
2. **검증된 페르소나** — 인터뷰 5-8명, 설문, 행동 데이터로 수정한 결과
3. **살아있는 페르소나** — 서비스 출시 후 실제 사용 데이터로 갱신

::: aside
인스타그램이 사진 필터 앱에서 SNS가 되고, 슬랙이 게임 회사 내부 도구에서 시작된 것처럼 처음 가설과 다른 사용자층이 발견되는 경우가 흔하다. 강사는 이 사례를 들어 "1차 가설이 틀려도 괜찮다"는 점을 강조한다.
:::

---

본 자료에서 만드는 것은 **1단계 가설 페르소나**이다. 완성이 목표가 아니다.

다음 단계의 검증 인터뷰가 무엇을 물을지 결정할 만큼만 구체적이면 된다.

::: aside
완성을 목표로 하면 작업자가 멈춘다. "이게 맞나?"라는 망설임이 워크시트 작성을 막는다. 가설 페르소나는 틀려도 되는 출발점이다.
:::

#### 1️⃣ 챕터 용어 해설

| 용어 | 정의 |
| --- | --- |
| **기획(Planning)** | 누구의 어떤 문제를 어떻게 풀 것인가의 답을 정의하는 일 |
| **페르소나(Persona)** | 서비스가 풀려는 문제를 가진 구체적 사용자상 |
| **페인포인트(Pain Point)** | 페르소나가 실제로 겪는 불편과 어려움 |
| **증상(Symptom)** | 표면에서 관찰되는 현상. 문제 자체가 아님 |
| **5 Whys** | "왜?"를 5번 물어 증상에서 진짜 문제로 내려가는 기법 |
| **1차 가설** | 검증 전 추측 단계의 가설. 틀려도 되는 출발점 |
| **가설 페르소나** | 데이터 없이 직관과 1차 리서치로 만든 첫 페르소나 윤곽 |
| **5단계 사슬** | 한 단계의 출력이 다음 입력이 되는 연결 구조 |

### 2️⃣ AI 시대 기획의 변화

이 챕터를 학습한 뒤 다음을 할 수 있다.

- AI로 빨라진 영역과 변하지 않은 영역을 구분한다
- 판단을 AI에 위임하지 않는 경계를 인식한다
- 영역별 AI 도구를 적절히 분리해 사용한다

#### 빨라진 것: 리서치

리서치는 사이클이 가장 크게 줄어든 영역이다.

```
[과거] 며칠 동안 검색 엔진과 자료를 손으로 뒤짐
       보고서 PDF 다운로드 → 키워드 추출 → 페르소나 윤곽
       총 1주일

[현재] ChatGPT/Gemini에 질문 → 분 단위로 후보 페인포인트
       총 몇 분
```

**핵심 도구**: ChatGPT, Gemini

::: aside
"5-30인 스타트업 PM의 회의록 정리 어려움"을 한 번 물으면 사례 5-10개가 출처 후보와 함께 돌아온다. 강사는 작업자에게 실제로 한 번 시도하게 한다.
:::

#### 빨라진 것: 문서화

문서화 사이클은 한 주에서 짧은 시간 단위로 줄었다.

```
[과거] 메모 → PRD 변환 (한 주)
       기능명세, 유저플로우, 와이어프레임을 각각 별도 도구로
       → 같은 정보를 세 번 입력

[현재] Manyfast가 PRD부터 와이어프레임까지 한 흐름
       → PRD 1회 입력으로 기능명세와 유저플로우 동시 산출
```

**핵심 도구**: Manyfast

#### 빨라진 것: 검증 사이클

검증 사이클은 가장 극적으로 줄어든 영역이다.

```
[과거] 가설 → 메일 카피 → 발송 → 응답 분석
       카피 작성에 하루, 발송 대상 정리에 며칠
       응답 모아 정리에 또 며칠
       총 보름 이상

[현재] 메타 프롬프팅으로 카피 후보 3개 동시 생성
       NotebookLM에 응답 모아 인용과 함께 분석
       총 하루
```

**핵심 도구**: 메타 프롬프팅 + NotebookLM

#### 빨라진 것: 데이터 스크래핑과 분석

```
[과거 - 스크래핑] 개발자가 며칠 동안 스크래퍼 작성
                 비개발자에게는 사실상 닫힌 작업

[현재 - 스크래핑] Playwright MCP에 자연어로 명령
                 "네이버 카페 글 30개를 CSV로 정리해줘"
                 → 짧은 시간 안에 결과
```

```
[과거 - 분석] 모은 글 100개를 직접 읽으며 패턴 추출
              며칠 + 분석자 편향 강하게 반영

[현재 - 분석] NotebookLM에 자료 업로드
              1-2시간 안에 공통 페인포인트 + 출처 정리
              인용 클릭으로 원문 즉시 검증
```

**핵심 도구**: Playwright MCP, NotebookLM

#### 5개 영역의 가속 정리

| 영역 | 과거 | 현재 | 핵심 도구 |
| --- | --- | --- | --- |
| **1차 시장 리서치** | 며칠 | 짧은 시간 단위 | ChatGPT, Gemini |
| **PRD 초안 작성** | 한 주 | 짧은 시간 단위 | Manyfast |
| **검증 사이클** | 보름 이상 | 하루 | 메타 프롬프팅 + NotebookLM |
| **데이터 스크래핑** | 며칠 | 짧은 시간 단위 | Playwright MCP |
| **페인포인트 분석** | 며칠 | 1-2시간 | NotebookLM |

작업자는 더 많은 가설을 더 빨리 시험할 수 있게 됐다. **그러나 가속은 가설의 품질을 높이지 않는다.**

### 두 번째 단정

> **AI는 기획을 대신하지 않는다. 기획의 속도만 바꾼다.**
> 

AI가 빠르게 만드는 것과 정확하게 만드는 것은 다르다. 가속은 사이클의 회전 속도를 바꾸지 가설의 품질을 바꾸지 않는다. **잘못된 가설을 빨리 검증하면 빨리 실패할 뿐이다.**

::: aside
빨리 실패하는 게 천천히 실패하는 것보다 낫지만, 실패 자체를 피하는 것은 가속만으로는 어렵다. 강사는 이 차이를 분명히 해서 작업자가 AI를 도구로만 쓰도록 유도한다.
:::

#### 변하지 않은 것: 판단의 영역

다음 세 영역은 가속해도 깊이가 깊어지지 않는다.

| 판단 영역 | AI의 역할 | 작업자의 역할 |
| --- | --- | --- |
| **페르소나 1명 그리기** | 후보 5-10명 빠르게 제안 | 1명을 채택하는 결정 |
| **페인포인트의 시장 신호 판단** | 자료에서 패턴 추출 | 본인 시장 적용성 판단 |
| **가설의 검증 가능성 점검** | (대신할 수 없음) | 검증 가능 형식 정의 |

**핵심 원칙**: 모으는 일은 가속하고, 판단하는 일은 깊게 한다.

::: aside
작업자는 AI를 속도의 도구로 쓰고 판단의 도구로 쓰지 않는다. 강사는 이 분리를 강조해 작업자가 ChatGPT 답변을 그대로 PRD에 옮기지 않도록 한다.
:::

#### AI에게 페르소나 묘사를 맡기지 않는다

AI는 평균을 만든다.

```
✅ AI가 만들 수 있는 것
"30대 직장인의 평균적인 하루"

❌ AI가 못 만드는 것
"한 주 5회 줌 미팅을 하는 5-30인 스타트업 PM이
회의 직후 어떤 동기로 어떤 행동을 하는가"
```

페르소나는 **행동·동기·맥락 세 축**으로 묘사된다. 이 셋 중 **동기**가 가장 자주 빠진다. 동기가 빠진 페르소나는 인구통계 카드일 뿐이며 의사결정에 도움이 되지 않는다.

#### AI 도구의 영역별 분리

| 영역 | 도구 |
| --- | --- |
| 1차 시장 리서치 | **ChatGPT, Gemini** |
| 출처 기반 자료 분석 | **NotebookLM** |
| PRD와 기능명세 | **Manyfast** |
| 코드 빌드 | **Claude Code** |
| 스크래핑과 E2E 테스트 | **Playwright MCP** |

**도구를 섞어 쓰면 가속의 효과가 사라진다.** 영역별로 도구를 분리하는 것이 운영 원칙이다.

#### 2️⃣ 챕터 용어 해설

| 용어 | 정의 |
| --- | --- |
| **AI 시대 기획** | AI 도구로 사이클이 빨라진 기획 방식 |
| **사이클(Cycle)** | 가설 수립에서 검증, 수정의 한 바퀴 |
| **속도와 깊이의 분리** | 가속은 속도를 바꾸지 깊이를 바꾸지 않는다 |
| **판단 위임의 함정** | 작업자가 판단을 AI에 맡기면 페르소나를 모른 채로 끝난다 |
| **행동·동기·맥락** | 페르소나를 묘사하는 세 축. 인구통계만으로는 부족 |

### 3️⃣ 출처 검증의 실전

이 챕터를 학습한 뒤 다음을 할 수 있다.

- AI가 만드는 거짓 정보의 3가지 패턴을 식별한다
- 출처 검증 3단계(클릭, 원문 확인, 신뢰성 판단)를 실행한다
- 검증된 정보와 검증 안 된 정보를 명확히 분리한다

#### 거짓 패턴 1: 그럴듯한 통계 🔴

**가장 위험한 패턴이다.**

AI는 정확해 보이는 숫자를 자주 만든다.

```
❌ AI 답변 예시
"한국 20-30대 PM의 78%가 회의록 정리에 30분 이상 쓴다"

→ 출처를 클릭하면 그런 통계가 없거나
→ 통계는 있지만 다른 모집단의 것
```

::: aside
작업자가 인용해 옮기면 다음 사람도 인용하는 사슬 효과가 발생한다. 검증되지 않은 통계는 노션 소개서까지 따라 올라간다. 강사는 이 점을 강조해 "한 번의 인용이 PRD까지 간다"는 위험을 인식시킨다.
:::

#### 거짓 패턴 2: 가짜 인용 🟡

**검증이 가장 어려운 패턴이다.**

AI는 유명인의 발언을 그럴듯하게 만들 수 있다.

```
❌ AI 답변 예시
"Marc Andreessen이 2010년에 Product-Market Fit을
다음과 같이 정의했다..."

→ 인용된 사람이 유명할수록 의심하지 않게 되는 함정
```

가짜 인용을 만나면 **인용을 그냥 빼는 것이 안전하다.** 1차 가설은 인용으로 강화되지 않고 페르소나의 진짜 목소리로 강화된다.

#### 거짓 패턴 3: 출처 조작 🟢

**가장 들키기 쉬운 패턴이다.**

AI는 URL이나 출판물 이름을 가공한다.

```
❌ AI가 만든 출처
"<https://kpma.or.kr/research/2023-pm-survey>"
→ 클릭하면 404 또는 무관한 페이지
```

**클릭만 하면 즉시 들킨다.** 출처 검증의 1단계가 "출처 클릭"인 이유가 여기에 있다.

#### 세 번째 단정

> **AI가 만든 답은 출처를 검증하지 않으면 사용 불가하다.**
> 

거짓이 발견되지 않을 수도 있다. 그러나 **AI 답변 5개 중 1-2개에 거짓이 섞여 있는 게 평균**이다. 발견되지 않았다면 다행이고, 발견됐다면 검증 능력을 키웠다는 신호이다.

#### 거짓 패턴 정리

| 거짓 패턴 | 위험도 | 검증 방법 |
| --- | --- | --- |
| **그럴듯한 통계** | 🔴 최대 | 통계 출처 URL 클릭 후 원문 확인 |
| **가짜 인용** | 🟡 중간 | 인용된 사람의 공식 자료 검색 |
| **출처 조작** | 🟢 경량 | URL 클릭 후 404 또는 무관한 페이지 확인 |

### 출처 검증 3단계 — 1단계: 클릭

AI 답변의 인용 또는 링크를 **직접 클릭한다.**

```
원칙: 클릭하지 않은 출처는 없는 것과 같다
```

AI가 답변에 출처를 첨부했다는 사실 자체는 검증 통과 신호가 아니다.

::: aside
흔한 함정은 본 적 있는 출처만 클릭하고 끝내는 것이다. 본 적 없는 출처가 거짓일 가능성이 높으므로 그것을 우선 클릭한다. 강사는 작업자가 친숙한 출처를 먼저 클릭하지 않게 유도한다.
:::

#### 출처 검증 3단계 — 2단계: 원문 확인

링크가 열린 페이지가 진짜 AI가 인용한 내용을 담고 있는지 점검한다.

**페이지가 열렸다고 통과가 아니다.** 페이지의 내용이 AI 답변과 일치해야 통과이다.

**점검 항목 4가지**:

- [ ]  페이지 제목이 AI가 인용한 글의 제목과 일치하는가
- [ ]  출판일과 저자가 AI 답변과 일치하는가
- [ ]  AI가 인용한 문장이 진짜 페이지에 들어 있는가
- [ ]  그 문장의 맥락이 AI 답변에서 인용된 맥락과 일치하는가

#### 출처 검증 3단계 — 3단계: 신뢰성 판단

원문이 진짜라도 신뢰 가능한지 작업자가 판단한다.

**판단 기준 3가지**:

- [ ]  1차 자료인가, 2차 자료인가
- [ ]  다른 출처와 교차 검증 가능한가
- [ ]  본인 페르소나에 적용 가능한 정보인가

**1차 자료가 아니거나 한국 시장 기준이 아니면 신뢰도가 낮다.**

#### 검증 흐름 정리

세 단계를 모두 통과한 정보만 워크시트에 옮긴다. **어느 한 단계라도 실패하면** 그 정보는 검증 안 된 정보로 분류해 별도 메모에 둔다.

```
AI 답변
    ↓ [1] 출처 클릭 (URL을 직접 클릭)
    ↓ [2] 원문 확인 (페이지가 진짜 그 내용인가)
    ↓ [3] 신뢰성 판단 (1차 자료인가, 검증 가능한가)
✅ 검증된 정보 → 워크시트에 옮김
❌ 어느 단계라도 실패 → 별도 메모로 분리
```

::: aside
이 3단계는 모든 학습 단계에 등장한다. 1차 리서치, NotebookLM 인용, sub-agent 보고, PRD 일치성 검증, 재피드백 분석에서 같은 절차가 반복된다.
:::

#### 3️⃣ 챕터 용어 해설

| 용어 | 정의 |
| --- | --- |
| **출처 클릭(Source Click)** | AI가 인용한 URL을 직접 클릭해 원문을 확인하는 행위 |
| **원문 확인(Original Reading)** | 페이지가 진짜 AI 답변의 내용을 담고 있는지 점검 |
| **신뢰성 판단(Trust Judgment)** | 1차 자료인가, 검증 가능한가, 다른 출처와 일치하는가 |
| **검증 우선주의** | AI 답변은 검증 전까지 사용 불가하다는 운영 원칙 |
| **그럴듯한 통계** | 숫자는 정확해 보이지만 출처가 없는 거짓 패턴 |
| **가짜 인용** | 유명인의 발언을 그럴듯하게 만든 거짓 패턴 |
| **출처 조작** | URL이나 출판물 이름을 가공한 거짓 패턴 |

## 실습

본 실습은 시드 6번(1인 스마트스토어 셀러 상세페이지 카피 생성기)을 일관된 예시로 사용한다. 본인 아이디어가 있다면 양식만 동일하게 따라하면 된다.

> 🎯 **실습 산출물**: 1차 가설 워크시트 (문제 정의 + 가설 페르소나 6줄 + 핵심 가설 3개)
> 

### 🌱 시드 아이디어 6개

본인 아이디어가 없거나 막연한 작업자를 위한 시드 6개. 본인 아이디어가 있으면 그것을 사용하고, 없으면 시드에서 1개를 선택한다.

### 시드 목록

| # | 시드 이름 | 페르소나 | 핵심 가치 |
| --- | --- | --- | --- |
| **1** | 회의록 액션아이템 추출기 | 5-30인 스타트업 PM | 회의 후 30분을 5분으로 |
| **2** | 학원·스터디 출결 알림봇 | 학원 원장, 스터디 운영자 | 출결 체크와 결석 알림 자동화 |
| **3** | 이력서 → 직무 적합도 진단기 | 신입~3년차 직장인 | 이력서를 채용공고에 맞게 수정 |
| **4** | 식단 사진 → 영양 분석기 | 다이어트 중인 20-40대 | 사진 한 장으로 칼로리 추정 |
| **5** | 소모임 정기일정 알림 자동화 | 동호회 총무, 소모임 리더 | 반복 공지 카피 자동 생성 |
| **6** | **1인 셀러 상세페이지 카피 생성** ⭐ | **1인 스마트스토어 셀러** | **상품 사진과 키워드로 카피 작성** |

> ⭐ **본 실습에서는 시드 6번을 일관된 예시로 사용한다.**
> 

### 시드 활용 가이드

```
복잡도: 5번 < 1번 < 2번 < 3번 < 6번 < 4번
```

- **4번**은 멀티모달 LLM API와 데이터 저장이 필요해 가장 복잡
- **비개발자**에게는 1번 또는 5번이 적합
- **주니어 개발자**는 어느 것도 가능

**시드는 출발점이지 종착점이 아니다.** 시드를 그대로 가져가지 않아도 된다.

- 페르소나 변형: "5-30인 스타트업 PM" → "10-50인 컨설팅 회사의 컨설턴트"
- 상황 변형: "줌 회의" → "1:1 인터뷰 녹음"
- 카테고리 변형: "회의록 정리" → "강의 영상 요약"

::: aside
비개발자 작업자를 위한 보조: 시드 6개 모두 BE(백엔드) 작업이 필요하다. LLM API 호출이 핵심 기능이기 때문이다. BE 셋업은 Claude Code가 자연어 명령으로 만들어 준다. 강사는 비개발자가 BE라는 단어에 부담을 느끼지 않도록 안심시킨다.
:::

### 활동 묶음 1: 아이디어 선택과 1차 리서치

본 활동의 목표는 시드 또는 본인 아이디어 1개를 선택해, 1차 리서치를 거쳐 **검증된 페인포인트 1-3개**를 손에 쥐는 것이다.

### 1-1. 아이디어 선택

**STEP 1**: 아이디어를 한 줄로 적는다.

빈 양식:

```
{누구}가 {어떤 상황에서 어떤 문제}를 겪는다.
```

시드 6번 적용:

```
1인 스마트스토어 셀러가 새 상품 등록 시
상세페이지 카피 작성에 한 상품당 1-2시간을 쓴다.
```

::: aside
이 한 줄이 안 나오면 아이디어가 모호한 것이다. 누구·상황·문제 셋이 모두 들어가는 한 줄이 합격선이며, 두 줄은 한 줄에 무엇을 넣을지 결정하지 못했다는 뜻이다.
:::

---

**STEP 2**: 적합성 점검

두 가지 적합성을 짧게 점검한다.

| 점검 항목 | 시드 6번의 답 |
| --- | --- |
| **왜 지금?** 이 문제가 *지금* 풀 만한가 | 스마트스토어 광고 단가 상승으로 카피 품질 압박이 어느 때보다 큼 |
| **왜 내가?** 페르소나에 닿을 수 있는가 | 1인 셀러 카페·커뮤니티 다수 존재, 본인 주변 부업 셀러 접근 가능 |

**두 질문 중 한쪽이라도 답이 약하면** 다른 시드 또는 다른 페르소나를 검토한다. 적합성이 낮은 아이디어는 검증 단계에서 컨택 리스트가 비어 무너진다.

---

**STEP 3**: 작업자 점검 체크리스트

- [ ]  누구·상황·문제 셋이 모두 들어갔는가
- [ ]  한 줄로 끝나는가
- [ ]  "왜 지금?" 점검을 통과했는가
- [ ]  "왜 내가?" 점검을 통과했는가

### 1-2. 5 Whys로 문제 깊이 파기

1-1에서 적은 한 줄은 보통 **증상**에 가깝다. 진짜 문제로 내려가기 위해 "왜?"를 3-5번 물어 본다.

빈 양식:

```
[증상] {1-1에서 적은 한 줄}
   ↓ 왜?
[1]
   ↓ 왜?
[2]
   ↓ 왜?
[3]
```

시드 6번 적용:

```
[증상] 상세페이지 카피 작성에 한 상품당 1-2시간이 든다
   ↓ 왜?
[1] 어떤 키워드를 넣어야 검색에 잘 잡히는지 매번 찾아본다
   ↓ 왜?
[2] 카테고리마다 검색 키워드 패턴이 다르고 트렌드가 바뀐다
   ↓ 왜?
[3] 키워드만 넣으면 부자연스러워 보여서 문장으로 다듬는 시간이 든다
   ↓ 왜?
[4] 부자연스러운 카피는 클릭률이 떨어진다는 경험이 있다
   ↓ 왜?
[5] 클릭률이 떨어지면 광고비 ROAS가 무너져 한 달 수익 직접 타격
```

**진짜 문제**: "정리 시간"이 아니라 **"키워드 자연화에 따른 ROAS 직접 타격"**

::: aside
답이 막히면 그 자리에서 멈춘다. 막혔다는 것 자체가 "이 문제는 작업자가 충분히 모른다"는 신호이며, 1차 리서치에서 보충해야 할 영역이다. 강사는 막힘을 부정적 신호가 아니라 1차 리서치의 입력으로 활용하게 안내한다.
:::

### 1-3. AI 1차 리서치

5 Whys로 도달한 문제 진술을 ChatGPT 또는 Gemini에 입력한다.

**STEP 1**: 1차 프롬프트

빈 양식:

```
{페르소나 후보}들이 {5 Whys로 좁힌 문제}에 대해
어떻게 느끼는지, 출처와 함께 알려줘.
한국 사용자 기준으로 답해줘.
```

시드 6번 적용:

```
1인 스마트스토어 셀러들이 상세페이지 카피의
키워드 자연화와 ROAS 압박에 대해 어떻게 느끼는지,
출처와 함께 알려줘. 한국 사용자 기준으로 답해줘.
```

---

**STEP 2**: 출처 점검

답변이 도착하면 **즉시 출처 URL이 있는지** 확인한다.

```
✅ 출처 URL 있음  → STEP 3로 진행
❌ 출처 URL 없음  → STEP 2-1 재요청
```

---

**STEP 2-1**: 출처 재요청 (필요 시)

```
방금 답변에서 통계 또는 인용 1개 이상에 대해
1차 출처 URL을 첨부해줘.
```

**그래도 출처가 안 들어가면** AI가 출처를 모른다는 신호이므로 그 답변은 사용하지 않는다.

### 1-4. 출처 검증과 거짓 메모

출처 검증 3단계를 순서대로 실행한다.

```
1. 본 적 없는 출처를 우선 클릭
2. 페이지가 진짜 답변 내용을 담고 있는지 확인
3. 1차 자료인지 본인이 판단
```

**거짓이 발견되면 폐기하지 않고 별도 메모에 옮긴다.**

빈 양식:

```
[검증 안 된 정보 메모]

- 정보: "{AI가 만든 통계 또는 인용}"
- 거짓 판정 이유: 출처 URL이 404 / 페이지가 무관 / 1차 출처 아님
- 다시 검증한다면 어디서: {1차 출처가 될 만한 곳}
- 어느 거짓 패턴인가: 그럴듯한 통계 / 가짜 인용 / 출처 조작
```

시드 6번 적용 예시:

```
[검증 안 된 정보 메모]

- 정보: "1인 셀러의 73%가 카피 작성에 2시간 이상 쓴다"
- 거짓 판정 이유: 출처 URL이 404
- 다시 검증한다면 어디서: 네이버 스마트스토어 공식 리포트, 셀러 커뮤니티 설문
- 어느 거짓 패턴인가: 그럴듯한 통계
```

---

**1차 리서치 정리** (검증을 통과한 정보만 옮김)

```
[1차 리서치 정리]

- 검증된 페인포인트 1: "{내용}". 출처: {URL}
- 검증된 페인포인트 2: "{내용}". 출처: {URL}
- 검증 안 된 정보: 위 메모 참조 (워크시트에 옮기지 않음)
```

::: aside
강사는 작업자가 "거짓이 발견 안 됐다"고 보고하면 다시 점검을 권한다. AI 답변 5개 중 1-2개에 거짓이 섞여 있는 게 평균이므로 0개 발견은 검증을 너무 빨리 끝낸 신호다.
:::

### ✅ 활동 묶음 1 검증 기준

- [ ]  아이디어를 한 줄로 말할 수 있는가 (누구·상황·문제 셋 다 들어감)
- [ ]  "왜 지금/왜 내가" 적합성 점검을 통과했는가
- [ ]  5 Whys를 최소 3번 적용해 진짜 문제를 좁혔는가
- [ ]  AI 리서치 답변에서 출처 URL 1개 이상을 직접 클릭했는가
- [ ]  클릭한 페이지가 진짜 AI 답변 내용을 담고 있었는가
- [ ]  검증된 정보와 검증 안 된 정보를 구분해 분류했는가
- [ ]  (있다면) 거짓 발견 메모가 있는가

### 활동 묶음 2: 워크시트 채우기

본 활동의 목표는 1차 리서치를 거친 입력을 **1·2·3단계 워크시트**로 정리하는 것이다.

### 2-1. 문제 정의 작성

빈 양식:

```
[문제 정의 워크시트]

- 누가: {페르소나. 짧고 구체적으로}
- 어떤 상황에서: {언제·어디서 이 문제를 만나는가}
- 어떤 어려움: {5 Whys로 도달한 진짜 문제}
- 그 어려움이 만드는 결과: {누락·지속될 때 무슨 일이 벌어지는가}
- 현재 어떻게 해결하나: {지금 사람들이 사용하는 방법}
```

시드 6번 적용:

```
[문제 정의 워크시트, 시드 6번]

- 누가: 1인 스마트스토어 셀러 (전업 1년차 전후, 월 50-100 SKU)
- 어떤 상황에서: 새 상품 등록 시, 사진 촬영을 마치고 카피를 작성할 때
- 어떤 어려움: 키워드를 자연스러운 문장으로 다듬는 데 시간이 든다
- 그 어려움이 만드는 결과: 카피 품질이 ROAS를 직접 결정해 한 달 수익에 타격
- 현재 어떻게 해결하나: 경쟁사 상세페이지 참고 + 본인이 직접 다듬기
```

::: aside
한 칸이라도 비면 1-1 단계로 돌아가 아이디어를 더 좁힌다. 특히 **"그 어려움이 만드는 결과"** 칸이 비면 5 Whys가 충분히 깊지 않았다는 결정적 신호다.
:::

---

**작업자 자가 점검**:

- [ ]  5줄 모두 한 문장으로 끝나는가
- [ ]  "그 어려움이 만드는 결과" 칸이 채워졌는가
- [ ]  누가·상황·어려움·결과·해결 5개가 명확히 구분되는가

### 2-2. 가설 페르소나 작성

본 활동에서 만드는 페르소나는 **가설 페르소나(Proto-persona)**이다. 데이터 없이 작업자의 직관과 1차 리서치만으로 만든 첫 윤곽이며, 다음 단계의 검증 인터뷰에서 수정된다.

**페르소나는 행동·동기·맥락 세 축**으로 묘사된다. 인구통계(나이·성별·연봉)만 가득한 페르소나는 의사결정에 도움이 되지 않는다.

빈 양식:

```
[가설 페르소나]

- 직군/역할: {예: 1인 스마트스토어 셀러}
- 환경 조건: {예: 월 50-100 SKU 등록, 광고 집행 중}
- 도구 사용: {예: 스마트스토어 에디터, 포토샵, 챗GPT}
- 동기/목표: {왜 이 문제를 해결하고 싶은가, 해결되면 무엇이 바뀌는가}
- 페인포인트 빈도: {예: 신규 상품 등록 시마다 = 주 2-5회}
- 검증 가능 채널: {예: 네이버 카페, 셀러 도구 사용자 커뮤니티}
```

시드 6번 적용:

```
[가설 페르소나, 시드 6번]

- 직군/역할: 1인 스마트스토어 셀러 (전업 1년차, 부업 출신)
- 환경 조건: 주방용품/인테리어 소품 중심, 월 50-100 SKU 등록, 광고 집행 중
- 도구 사용: 스마트스토어 에디터, 포토샵/캔바, 챗GPT(가끔 카피용)
- 동기/목표: 카피 시간을 줄여 상품 발굴과 사진 촬영에 시간을 쓰고 싶다.
            상품 발굴이 매출의 80%인데 지금은 카피에 시간을 빼앗기고 있다.
- 페인포인트 빈도: 신규 상품 등록 시마다 = 주 3-5회 발생
- 검증 가능 채널: 네이버 카페 "스마트스토어 셀러 모임",
              이지어드민/사방넷 사용자, 본인 주변 부업 셀러
```

---

**여섯 줄 중 두 줄이 결정적이다.**

| 결정적 줄 | 이유 |
| --- | --- |
| **동기/목표** | 비면 인구통계 카드. 메일 카피의 후크와 인터뷰 질문이 만들어지지 않음 |
| **검증 가능 채널** | 비면 카피 발송 대상이 누구인지 모름. 페르소나가 모호하다는 결정적 신호 |

::: aside
강사는 동기/목표 칸을 작성자가 "회의 직후 본업으로 돌아가고 싶다" 같은 *행동의 이유*로 적었는지 점검한다. "효율적으로 일하고 싶다" 같은 공허한 문장은 동기가 아니다.
:::

### 2-3. 핵심 가설 3개 도출

**가설은 직감으로 만들지 않는다.** 1-4의 검증된 페인포인트 1-2개를 가져와, 그 각각에 대해 "이 페르소나가 ~할 의향이 있는가"를 물을 수 있는 형태로 변환한다.

> **검증된 페인포인트와 매핑되지 않는 가설은 검증할 데이터가 없으므로 다음 단계에서 무너진다.**
> 

---

**가설 형식 2가지**:

```
형식 1: "이 사람들은 ~할 의향이 있을 것이다"
형식 2: "이 사람들은 ~보다 ~를 더 선호할 것이다"
```

**검증 가능성 비교**:

```
❌ "쓸 만하다"                          → 검증 불가능
✅ "월 1만원 이상 지불할 의향이 있다"   → 검증 가능
```

---

시드 6번 적용 가설 3개:

```
[핵심 가설 3개, 시드 6번]

가설 1 (페인포인트 "키워드 자연화 부담"에서 변환):
"1인 스마트스토어 셀러는 키워드를 자연스러운 카피로 바꿔주는 도구에
월 2만원 이상 지불할 의향이 있을 것이다."

가설 2 (페인포인트 "카테고리별 키워드 트렌드 추적"에서 변환):
"셀러는 카피 생성보다 카테고리별 키워드 추천에
더 큰 가치를 느낄 것이다."

가설 3 (페인포인트 "ROAS 직결 카피 품질 압박"에서 변환):
"셀러는 AI 자동 작성 전체보다 키워드 제안 + 본인 작성을
더 선호할 것이다."
```

---

**작업자 자가 점검**:

- [ ]  가설 3개 모두 검증 가능한 형식인가
- [ ]  가설 3개가 1-4의 검증된 페인포인트와 명시적으로 매핑되는가
- [ ]  각 가설이 한 문장으로 끝나는가
- [ ]  가설의 핵심 단어가 데이터로 식별 가능한가 (지불 의향, 선호 등)

### ✅ 활동 묶음 2 검증 기준

- [ ]  문제 정의 5줄을 짧고 구체적으로 채웠는가
- [ ]  "그 어려움이 만드는 결과" 칸이 채워졌는가
- [ ]  페르소나 6줄을 채웠는가
- [ ]  동기/목표 칸이 인구통계가 아닌 행동의 이유를 담고 있는가
- [ ]  핵심 가설 3개가 검증 가능한 형식인가
- [ ]  가설 3개가 1-4의 검증된 페인포인트와 매핑되는가
- [ ]  검증 가능 채널이 명시됐는가

### 활동 묶음 3: 자기 선언과 회고

본 활동의 목표는 작성한 1차 가설을 **다른 사람에게 한 줄로 전달 가능한 형태**로 다듬는 것이다.

### 3-1. 옆 작업자에게 선언

빈 양식:

```
"풀려는 문제는 {문제}이고
페르소나는 {페르소나}이다.
핵심 가설 1개는 {가설}이다."
```

시드 6번 적용:

```
"풀려는 문제는 1인 셀러의 키워드 자연화에 따른 ROAS 타격이고
페르소나는 월 50-100 SKU 등록하는 전업 1년차 스마트스토어 셀러이다.
핵심 가설 1개는 키워드를 자연스러운 카피로 바꿔주는 도구에
월 2만원 이상 지불할 의향이 있다는 것이다."
```

---

**검증 방법**:

```
❌ "이해됐어?" → 거짓말하기 쉬운 질문
✅ "네가 들은 것을 한 줄로 다시 말해봐"
```

다시 말한 내용이 본인 의도와 일치하면 명확한 것이고, 일치하지 않으면 본인의 표현이 모호한 것이지 듣는 사람의 문제가 아니다.

::: aside
1차 가설이 다른 사람에게 한 번에 전달되는가가 메일 카피의 응답률을 결정한다. 한 줄로 말하지 못하는 가설은 메일에 한 줄로 적을 수 없다. 강사는 이 활동을 통해 작업자가 가설을 압축하는 능력을 점검하게 한다.
:::

### 3-2. 회고 3개 질문

다음 3개 질문에 짧게 답한다.

```
1. 가장 어려웠던 부분은 무엇인가
2. 출처 검증에서 거짓이 몇 개 발견됐는가
3. 다음 단계 검증으로 가져갈 가설은 어느 1개인가
```

**좋은 답과 나쁜 답의 차이는 구체성에 있다.**

| 질문 | 좋은 답 (구체적) | 나쁜 답 (모호) |
| --- | --- | --- |
| **가장 어려웠던 부분** | "페르소나 6줄 중 동기/목표를 채우는 게 어려웠다" | "전반적으로 어려웠다" |
| **거짓 발견 수** | "2개. 통계 1개와 인용 1개" | "잘 모르겠다" |
| **다음 단계 가설** | "가설 1번(월 2만원 지불 의향)을 메일로 검증" | "가설 3개 다 가져간다" |

좋은 답은 다음 단계의 입력이 된다. 나쁜 답은 다음 단계에서 다시 작성해야 한다.

### 3-3. 다음 단계 진입 점검

다음 3개 자산이 손에 있어야 다음 단계로 진입 가능하다.

```
[다음 단계 진입 자산]

✅ 완성된 1차 가설 워크시트
   - 문제 정의 5줄
   - 가설 페르소나 6줄
   - 핵심 가설 3개

✅ 검증 가능 채널 1-3개

✅ 1차 리서치 정리 (검증된 페인포인트 1-3개)
```

**세 자산 중 하나라도 비어 있으면** 과제에서 그것부터 채운다.

::: aside
다음 단계의 첫 활동이 메일 카피 작성이며, 카피의 첫 줄(후크)에 1차 가설이 한 줄로 들어간다. 한 줄로 쓰지 못한 가설은 카피의 후크가 되지 못한다. 강사는 작업자가 "가설을 한 줄로 압축할 수 없다면 1단계로 돌아가야 한다"는 점을 명확히 전달한다.
:::

### ✅ 활동 묶음 3 검증 기준

- [ ]  옆 작업자가 1차 가설을 한 줄로 다시 말할 수 있었는가
- [ ]  회고 3개 질문에 모두 구체적으로 답했는가
- [ ]  다음 단계로 가져갈 가설 1개를 결정했는가
- [ ]  다음 단계 진입 자산 3개가 손에 있는가

본 활동의 산출물(1차 가설 워크시트)이 과제의 출발점이다. **활동에서 채운 워크시트를 그대로 가져가서 컨택 리스트를 추가하면 과제 완성이다.**

### ⭐ Tips: 함정과 처방

- **1차 가설은 틀려도 된다** — 첫 가설이 그대로 살아남는 비율은 평균 30% 미만. "확실한 것만 적자"는 자세가 가설 작성을 가장 많이 막는다.
- **5 Whys는 3번이면 충분하다** — 5번까지 가는 게 목표가 아니다. 답이 막히는 지점이 진짜 문제이며, 거기서 멈추면 된다.
- **출처 검증은 한 번에 익히지 않는다** — 한 주에 한 번씩 직접 클릭해 보는 습관. 첫 한 달이면 거짓을 알아보는 직관이 생긴다.
- **페르소나는 좁을수록 검증이 쉽다** — 좁히는 것은 페르소나의 수를 줄이는 것이 아니라 윤곽을 명확하게 만드는 일.
- **동기/목표가 빠진 페르소나는 인구통계 카드일 뿐** — "왜 이 문제를 해결하고 싶은가"가 채워져야 한다.
- **시드는 출발점이지 종착점이 아니다** — 페르소나 또는 상황만 본인 관심사에 맞춰 변형하면 본인 자료가 된다.
- **컨택 리스트는 만나본 적 있는 사람부터** — 콜드 메일 응답률은 5-15%. 친구의 친구가 페르소나면 그 한 명이 가장 강한 컨택.
- **AI에게 페르소나 묘사를 맡기지 않는다** — AI는 평균을 만든다. 작업자가 직접 한 명을 그려야 검증 가능한 페르소나가 된다.
- **1차 가설을 한 줄로 적었으면 절반은 끝난 것** — 두 줄 이상이면 페르소나·문제·가설 중 하나가 모호한 것.
- **거짓 0개 발견은 자랑이 아니다** — AI 답변 5개 중 1-2개에 거짓이 섞여 있는 게 평균. 0개라면 검증을 너무 빨리 끝낸 신호.
