# 과제: PRD 완성과 Manyfast 프로젝트 완성

## 목표

다음 학습 단계 시작 전까지 PRD를 완성하고 Manyfast 프로젝트를 다음 단계의 MCP 연동 대상으로 준비한다. prd.md 파일이 작업 폴더에 export된 상태로 다음 단계에 진입한다.

---

## 산출물

다음을 다음 단계 시작 전까지 완성한다.

- **NotebookLM 노트북**: 전체 데이터 업로드와 페인포인트 5개 정리
- **Manyfast 프로젝트**: PRD + 기능명세서 + 유저플로우(최소 1개) + 와이어프레임(최소 1개)
- **prd.md 파일**: 작업 폴더에 export 완료
- (선택) NotebookLM 인용 검증 메모 3건 이상

---

## 최소 인정 범위

- NotebookLM 페인포인트 5개 추출
- Manyfast PRD만 (기능명세·유저플로우·와이어프레임 일부 미완성 허용)
- prd.md export 완료

---

## 권장 범위

- NotebookLM 페인포인트 5개 + 인용 검증 3건 이상
- Manyfast PRD + 기능명세 + 유저플로우 + 와이어프레임 모두 + 각 단계 검토 수정
- 모호한 표현 3개 이상 직접 수정한 흔적
- 핵심 기능을 3개로 좁히고 제외 기능을 제약사항에 명시

---

## 자가 점검 체크리스트

- [ ] 페인포인트가 데이터에서 나온 것인가, 직감인가
- [ ] PRD에 모호한 표현이 0건인가
- [ ] 성공 지표가 측정 가능한 형태인가
- [ ] 핵심 기능이 3개 이하인가
- [ ] 페르소나가 짧고 구체적인가
- [ ] prd.md 파일이 작업 폴더에 있는가

---

## 막혔을 때

| 시나리오 | 대응 |
| --- | --- |
| **페인포인트가 모이지 않는다** | NotebookLM에 키워드를 바꿔 재질문한다. "가장 자주 등장하는 불만"이 안 모이면 "사람들이 매주 시간을 쓰는 어려움"으로 |
| **PRD가 모호하다** | "이 PRD를 비개발자가 읽고 30초 안에 무엇을 만들지 이해할 수 있는가" 자문한다 |
| **기능이 너무 많다** | "이 중 1개만 남긴다면 무엇인가"로 우선순위를 정한 뒤 2-3개로 추가 좁힌다 |
| **인용이 가짜이다** | NotebookLM의 인용을 클릭해 원문을 확인한다. 가짜이면 그 페인포인트는 제외하고 다른 인용으로 대체 |
| **Manyfast 자동 검토가 너무 많이 지적한다** | 자동 검토 결과를 그대로 받지 않는다. 작업자가 의도한 모호함과 의도하지 않은 모호함을 구분 |

---

## PRD 검토 5개 점검 (export 전 필수)

prd.md를 export하기 전에 다음 5개를 본인이 직접 점검한다.

- 페르소나 5줄이 짧고 구체적인가
- 핵심 기능이 3개 이하인가
- 각 기능에 검증 가능한 성공 지표가 있는가
- 제약사항이 명시됐는가
- 모호한 표현이 0건인가

5개 중 하나라도 미통과면 Manyfast로 돌아가 수정한 뒤 다시 export한다.
