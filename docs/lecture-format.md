# Lecture Format SSOT

> 강의 자료(`lecture.md`) 작성 표준. lecture-translator α.1 파싱의 입력 정의.
> v2 핵심 변화: 자유 형식 → **4계층 헤더 표준**.

---

## 1. 헤더 4계층

| 레벨 | 의미 | 사용 횟수 |
|---|---|---|
| `#` | 수업 전체 제목 | 파일당 1개 |
| `##` | 이론/실습 구분 | 정확히 2개 ("이론", "실습") |
| `###` | 챕터 | N개 |
| `####` | 슬라이드 묶음 (1-5장) | N개 |

### `#` — 수업 제목
파일 맨 위 1개. 사이트 최상위 제목.

### `##` — 이론/실습
정확히 2개. "이론", "실습" 고정. 탭/섹션 분기점.

### `###` — 챕터
이론·실습 안에서 챕터 분할. 번호 이모지(1️⃣) 또는 일반 번호.

### `####` — 슬라이드 묶음 ⭐
**가장 중요한 레벨**. 1-5장 슬라이드로 펼쳐짐.
- 1 `####` 안 콘텐츠가 한 슬라이드에 들어가면 1장
- 분량 많거나 흐름 끊고 싶으면 `---` 사용 (최대 5장)

---

## 2. `####` 안 슬라이드 자르기 — `---`

```markdown
#### 기획의 정의

기획은 누구의 어떤 문제를 어떻게 풀 것인가의 답을 정의하는 일이다.

---

세 개의 핵심 질문:
- 누구 (페르소나)
- 어떤 문제 (페인포인트)
- 어떻게 (솔루션)
```
→ 2장의 슬라이드.

### 자르는 시점 판단
- 핵심 메시지가 바뀜 (개념 정의 → 적용 사례)
- 시각적 표현 방식 바뀜 (텍스트 → 표)
- 분량 많음 (4문장 초과 또는 슬롯 4개 초과)
- 라이브 강의 호흡 끊고 싶은 지점

### 1-5장의 의미
- 1장: 짧은 개념, 한 단정, 용어 정의
- 2-3장: 일반적인 콘텐츠
- 4-5장: 복합 콘텐츠 (단계별, 여러 사례)

⚠️ 5장 초과 → `####` 두 개로 쪼개기 신호.

---

## 3. 슬라이드 콘텐츠 작성 규칙

각 슬라이드 구조:
```markdown
#### {제목}

{본문: 핵심 메시지 + 부연 설명}

::: aside
{자습 모드 전용 보충 설명}
:::
```

### 핵심 메시지
첫 단락. 한 문장 이상적, 두 문장 이내.

### `::: aside` 블록
자습 모드 전용 보충. 슬라이드당 1개, 3-4문장 이내.
핵심 메시지 없이도 슬라이드 성립해야 함.

### 강조 인용 — `>` 블록
핵심 단정 강조. `quote` 타입으로 자동 매핑.
```markdown
#### 첫 단정

> 기능을 정하기 전에 사람과 문제를 정한다.

좋은 기획은 페르소나에서 출발하기 때문에 검증 가능하다.
```

### 표
비교/정리. `comparison` 또는 `terms` 타입 자동 매핑.

### 번호 리스트
단계/절차. `process` 타입 자동 매핑.

## 5. 자가 점검 체크리스트

- [ ] `#` 정확히 1개
- [ ] `##` 이론/실습 2개
- [ ] 모든 `###` 챕터에 `####` 또는 본문 존재
- [ ] 어떤 `####`도 5장 초과 X
- [ ] 각 슬라이드 핵심 메시지 1-2문장
- [ ] `::: aside` 슬라이드당 1개 이하
- [ ] 표/번호 리스트/`>` 인용 중 한 가지만 명확하게 사용

## 6. 빌드 시점 검증

| 검증 항목 | 위반 시 |
|---|---|
| `#` 정확히 1개 | ❌ 빌드 에러 |
| `##` 정확히 "이론"+"실습" | ❌ 빌드 에러 |
| 모든 `###` 하위에 `####` 또는 본문 | ❌ 빌드 에러 |
| `####` 슬라이드 ≤ 5장 | ⚠️ 경고 |
| 슬라이드 타입 결정 | ❌ 빌드 에러 |
| `::: aside` ≤ 1/슬라이드 | ⚠️ 경고 |

## 7. 빌드 흐름

```
lecture.md (LECTURE_FORMAT.md 준수)
  ↓
파싱: # → 제목 / ## → 분기 / ### → 챕터 / #### + --- → 슬라이드
  ↓
자동 매핑: 콘텐츠 패턴 → 8타입 (docs/slide-types.md)
  ↓
렌더링: 각 슬라이드 → React 컴포넌트
  ↓
빌드: Next.js 정적 사이트
```

## 9. 헤더 분류 룰 (D-033 적용)

> **2026-05-11 갱신**: `###` = 섹션 표지 / `####` = 세부 콘텐츠 (구조 재해석).
> 자동 생성 슬라이드: `#` → 세션 표지 / `## 이론`·`## 실습` → 덱별 목차 (D-032).

### 9.1 판정 규칙 (단순화)

| 헤더 패턴 | 분류 | 자동 생성 슬라이드 | 예시 |
|---|---|---|---|
| `# ` | 수업 제목 | **세션 전체 표지** (Cover) | `# 기획의 본질과 문제 발견` |
| `## 이론` | 이론 덱 진입 | **이론 목차** (Objectives) | `## 이론` |
| `## 실습` | 실습 덱 진입 | **실습 목차** (Objectives) | `## 실습` |
| `### {제목}` | 섹션 표지 | **섹션 표지 슬라이드 1장** (Cover) | `### 1️⃣ 기획이란 무엇인가` |
| `#### {제목}` | 세부 콘텐츠 묶음 | (콘텐츠 슬라이드 1-N장, `---` 분할) | `#### 기획의 정의` |

⭐ **모든 `###` = 섹션 표지** (emoji 유무 무관). 학생 화면에서는 emoji 제거.

### 9.2 `---` separator

`####` 세부 콘텐츠 안에서 `---` = 슬라이드 경계. 한 `####` 묶음 ≤ 5 슬라이드 권장 (WARN).

### 9.3 미니 사이클 단위 (D-034)

- **미니 사이클 = `###` 섹션 전체**
  - 표지 1장 (Cover, ### 헤더 + 본문 학습목표를 objectives로)
  - 모든 `####` 세부 콘텐츠 슬라이드 (각 1-N장)
- 한 미니 사이클 슬라이드 수: 1-15장 (가변)

### 9.4 자동 생성 슬라이드 상세

**세션 표지** (`#` 헤더 trigger):
- 위치: 모든 슬라이드 1번
- Cover 패턴: `title` = `#` 텍스트 / `subtitle` = 자료 첫 단락 한 줄 요약

**덱 목차** (`## 이론`/`## 실습` 직속 trigger):
- 위치: 각 덱 시작 직후 (이론은 # 다음, 실습은 이론 끝 다음)
- Objectives 패턴: `eyebrow` = `"이론 구성"` / `"실습 구성"` / `items` = 하위 `###` 제목 목록

**섹션 표지** (`###` 헤더 trigger):
- 위치: 각 `###` 시작
- Cover 패턴: `title` = `###` 텍스트(emoji 제거) / `objectives` = `###` 직후 학습목표 bullet list (있으면)

### 9.5 호환 모드 (deprecated)

기존 v2 4계층 표준은 폐기. 모든 lecture.md는 본 § 9 룰 따름.
